# Review, repair, resume and finish

## Inspect what exists

Read the requested scope, prior scene/prompt, current bible and supplied media. Use the host's native image viewer on each actual frame. For video, use supported local frame extraction or playback and inspect the times relevant to the claim. On macOS, existing sips, qlmanage or mdls may help inspect format, thumbnails or duration; inspect their help before use. Do not assume ffmpeg, Pillow or another dependency is installed. A thumbnail proves only the view it contains. If viewing is unavailable, identify that specific unverified step.

Compare the intended crop against identity/state, geography, light, prop ownership and performance. Check for shadows that disagree with illumination, plausible-looking broken geometry, impossible local relationships and smeared/oily material. A still defect that will affect motion blocks that shot's readiness. Two stills do not prove temporal consistency, lipsync or audio quality.

Write findings as observed fact, expected relationship, earliest likely cause and one proposed correction. Distinguish asset error, geography, performance, shot direction, target uncertainty and inconclusive evidence. Do not infer a generation's actual settings from its look. Check the actual prompt and references before rewriting them.

## Film Advisor's bounded repair

1. Review read-only against the current brief and visible evidence. List consequential findings with artifact locations. The review itself grants no edit authority.
2. Select the earliest causal failure the user authorized repairing. State one changed variable and what will stay fixed. Several textual occurrences may need changing to express the same single correction; this is not permission to redesign the scene. Map, position and camera-axis corrections belong to the geography variable; source-count and shadow-direction corrections belong to a separate lighting variable. Do not combine geography and lighting as one scene-lock repair: preserve the unselected cause and report its remaining defects.
3. Apply one repair round within the approved paths. Preserve the prior revision and successful unrelated work. Run affected compiler/checker steps and inspect the changed prompt or frame against the same findings.
4. Return a verified correction or a named remaining failure. Escalate after this recheck; do not start another loop or generate a clip to make the example green.

Use a fresh read-only helper only when available, useful and authorized. Pass the bounded question, exact current artifacts, inherited authority and return requirements. A fixer does not approve its own work. The parent verifies evidence and gives the final result. When no independent helper ran, call the check self-review. Model and effort identities stay observed or unknown, never invented.

An example review note:

    Observed: The prop is visible in the left hand in frame A and the right hand in frame B; no transfer is shown.
    Expected: The approved left-hand hold continues through this cut.
    Cause to test: Shot B's first-frame instruction omitted the holder.
    Change: Add that holder binding to Shot B only.
    Preserve: Identity, camera side, dialogue, light, timing and all other shots.
    Recheck: Compare the revised prompt to the lock. A new rendered frame is still needed to prove the visual repair.

## Resume and evidence-led iteration

Start at the last real result. Read current instructions, the source revision, compiled outputs and the prior review. Run status with the same target selection used for compilation. Preserve settled decisions unless current authority changes them.

For a changed asset/state/style/geography/voice, identify its dependent shots. Refresh only the authorized references and scene adaptations; rerun affected checks. A changed source makes dependent old prompts stale even if they still look plausible. The compiler preserves unaffected output bytes. If manual output edits exist, reconcile them into the source before using the documented repair option. Removed shots remain historical; do not delete them merely to get a clean status.

Record an actual attempt concisely:

    Revision and shot:
    Hypothesis / one changed variable:
    Preserved inputs:
    Authorized attempt/spend limit and usage:
    Observed output or unavailable proof:
    Earliest diagnosis:
    Next bounded step or stop:

For a future authorized generation, record actual provider job/output identifiers only when exposed. Keep planned attempts distinct from submitted, failed and inspected attempts. Reuse successful material. When the configured failure budget is reached, simplify or ask for a changed plan; do not silently reset the count. One failure is evidence about its conditions, not a universal model ranking.

## Stop at the real execution gate

Before any paid generation, name the service, material to upload, desired operation, cost exposure and available approval. Do the same for authentication, purchase, destructive replacement, publication and scope expansion. Verify current controls and rights. If the necessary approval/tool is absent, return the usable prompt and the precise next step. A compiler pass does not authorize a provider call. Never label a text package a rendered film.

## Finish and prepare delivery

Assemble selected shots for story first. Keep source IDs and revisions so edits can be reconstructed. Prioritize defects affecting faces, hands, readable text and continuity. Unify neighbouring exposure and colour before adding a scene look. Clean dialogue, bridge ambience, place effects, then decide music and final mix. Keep generated SFX/dialogue separate from post-production music choices.

For delivery readiness, inspect actual file existence, format, dimensions, duration, captions if requested, audio audibility, opening/ending, rights/credits, intended destination and requested variants. Check the whole sequence, not just its strongest frame. Use native metadata tools for measured properties and actual playback for perceptual claims. Missing tools or missing final media leave those checks unverified.

Return only what is ready: planning package, reviewed media, or approved delivery package. Sending/uploading/publishing stays a separate authorized action. Close with the single most useful workflow lesson tied to observed evidence. Suggest a reusable change; do not rewrite global instructions or install anything as a retrospective side effect.
