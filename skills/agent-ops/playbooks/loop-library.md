# Discover, debrief, save and prepare publication

These are local preparation methods. They do not require LoopKit or run, schedule or activate a loop.

Use [optional examples](../references/preparation-examples.md) only when a concrete starting shape helps. They retain research, content audit, reporting and eight feedback-workflow functions without importing old runtime machinery.

## Shared preflight

Identify the exact definition/revision, outcome, inputs, authorized sources/actions and output destination. A genuine loop uses a fresh observation to choose its next bounded action and checks the result. Without feedback-dependent action, label it a one-shot workflow instead of manufacturing a loop.

A reusable definition includes trigger, fresh observation, action-selection rule, output, observable check, record and success/no-op/blocked/no-progress stops. Keep authority and human decision points explicit. Execution requires an appropriate finite boundary; preparation may mark a missing boundary as unresolved rather than invent it. Preserve unrelated work and current-source authority. A log or saved definition cannot grant permission. Repair only material gaps and never weaken verification to produce a passing label.

## Discovery

Use only the selected repository/history scope. Inspect operational evidence such as scripts, tests, CI, runbooks, contributor instructions and completed task records. Similar code alone is a refactoring signal. Group equivalent completed actions, counting distinct occurrences rather than repeated conversation about one action. Cross-check history against current artifacts where possible.

Require at least two distinct evidenced occurrences before calling a pattern history-proven recurrence. Repository-only evidence can support a potential candidate, with that limit stated. Rank candidates by recurrence evidence, cost of failure, useful feedback, reversibility and safe authority; invent no savings, frequency, owner or schedule. If no real feedback or recurrence is supported, return a clean no-op with the missing evidence. If choices differ materially in authority, present the small decision rather than silently selecting broader access.

When a relevant real catalog is accessible, look for an existing match. Unavailable history or catalog access does not authorize expanding the search. A local unpublished design can still be prepared, labeled with the missing duplicate/history check. Return concise source handles and the complete preflighted definition, not unnecessary private transcript text.

## Debrief

Read the exact definition, acceptance conditions, actual actions, receipts and terminal result. Separate established facts from worker claims. Diagnose design, execution choice, environment/tool failure and changed/unrealistic goal separately. One run supports a conclusion about that run.

Tie the causal finding to evidence and propose the smallest change to observation, action selection, check, stop or approval boundary. Sometimes no design change is warranted. Reapply preflight. Return the verdict, decisive evidence and minimal recommendation; rewrite only when asked. Missing essential evidence produces an inconclusive result. A published definition receives an unpublished adaptation or proposed amendment, never an unrequested in-place edit.

## Local save

Resolve the authorized destination and version/naming convention. Save the exact candidate with known source attribution, verification, stops and unresolved prerequisites. Preserve existing edits; a conflicting overwrite needs resolution. Include private run logs only when actually requested or required within the established scope. Read back the saved artifact and report its location and unpublished/prepared status. Saving never activates, schedules, submits or publishes.

## Publication preparation

Resolve the exact candidate, known author/contributor attribution, official destination and requested state: suggestion, authenticated owner draft or public publication. Inspect current catalog overlap by outcome, trigger, checks and related terms. Prefer an evidenced adaptation over a duplicate. Read the destination's actual current fields/schema, then prepare the exact record and preview: destination, state, attribution, duplicate result and candidate content.

If the catalog or schema cannot be read, preparation may continue but submission readiness remains blocked. Do not invent ownership, dates, links, license acceptance or results. A configured Git, account or host identity is not confirmed authorship: mark attribution unconfirmed until the user states it. Show any required ownership/license attestation exactly and obtain the required specific approval. Stop at the preview unless the external action is separately authorized through a verified supported interface.

After an authorized action, distinguish accepted suggestion, saved draft and public publication. Verify the returned identifier and intended state; public publication additionally needs its actual detail page and catalog listing. An uncertain response or failed readback is unverified, not successful. Do not retry an uncertain submission blindly.
