# Evidence that fits the criterion

A level labels the kind and provenance of an observation. It is not a universal score. A deterministic parser can establish syntax while saying nothing about a source claim, visual preference or real permission.

## Evidence kinds

| Kind | What it can support | What it cannot establish alone |
|---|---|---|
| E0 writer reflection | A hypothesis, possible defect or next revision | Verified completion or learning benefit |
| E1 model review or heuristic | A cited critique, triage or reasoned proposal | Independent truth, authenticated consent or direct human preference |
| E2 direct human judgment or authenticated external observation | The exact stated choice or observed fact within its scope | Unrelated criteria, future permission or general benefit |
| E3 actual deterministic check | Its frozen predicate on the bound inputs/artifact/environment | Semantic correctness beyond that predicate, exhaustive privacy or human approval |
| E4 repeated provenance-independent E2/E3 plus held-out/postcondition evidence | The declared stronger supported claim | Automatic promotion, universal safety or causality outside the study |

If a contract requires a specific kind, a nominally higher label of another kind does not replace it. A direct choice remains missing until the real person makes it. A source-grounded argument needs actual source inspection; a structural completeness test cannot supply it. Self-report and imported fields retain their provenance regardless of their declared label.

## Define each required criterion

Write the question the check answers, the named artifact/version, required sources, acceptable evidence kind, expected result, known failure signal and missing-evidence response. Identify the producer, evaluator and reviewer separately. Freeze the expectation before looking at the candidate's score.

For a command check, name the exact verifier and configuration, candidate/source/test-data identities, relevant environment and dependency versions, timeout/output bounds and the predicate. A successful process exit is insufficient if it never exercised the requested behavior. Conversely an expected nonzero negative test can correctly demonstrate rejection. Keep that result separate from successful task execution.

Use explicit pass, fail, missing, blocked, inconclusive, stale or invalid findings. All required criteria need current adequate evidence; optional success does not compensate. Include failed, superseded and withheld observations in the history. A later green result may resolve an earlier failure only when the new artifact/check relationship is explicit. It never changes the old attempt's grade.

## Four domain mappings

### Code and operational tasks

Exercise the public entry and real behavior. Use independent literal expected values or independently derived oracles. Inspect exact returned content, state change and relevant postconditions. Type/build/lint checks complement behavior; they do not prove the requested path ran. A bug test must fail for the original defect, then the actual fixed path and affected happy path must pass. Use isolated input and retain exact test output.

Review scope and side effects. Match the intended workspace, target and action. A wrapper is not an OS sandbox; process exits do not certify that unrelated files stayed unchanged. Where preservation matters, compare the explicitly protected files/state before and after. Do not claim protection of sources never inspected.

### Research and factual analysis

Bind claims to actual inspected source passages and their dates. Separate current primary evidence, inherited access notes, reported claims, inference and unknowns. Check that each citation entails the nearby claim, the population/denominator and qualifiers survive, contradictions are disclosed, and the answer addresses the original question. A link existing or a reference count is not entailment.

When a source changes, re-evaluate affected claims and derived results. Retain claims that no longer hold as historical rather than silently carrying them forward. Freshness is task-dependent and must be declared. Missing authoritative access yields a scoped answer or no-decision, not an invented full read. A model reviewer can critique this work; label its independence and the actual source checks accurately.

### Structured artifacts

Validate the artifact people will open, not a template or intermediate file. Check required rows/sections, literal values, formulas, units, totals, denominators, links and file-open behavior as applicable. Inspect actual rendered pages or interactive states when legibility, layout or behavior matters. A valid JSON/CSV/PDF structure alone does not prove usability or semantic correctness.

For transformed data, preserve the input set and transformation rule. An omitted row may make a total look plausible while the job is incomplete. Use known-bad fixtures and compare final-byte identity to the checked version. If rendering/opening is unavailable, keep that criterion unverified rather than inferring it from successful export.

### Creative or preference-led work

Distinguish brief compliance from preference. Check the actual rendered image/video/audio or readable text where that is the requested output, not only its prompt or file metadata. Preserve reference identity, requested changes, exclusions and stated format. Direct user selection or a declared pairwise preference can satisfy the corresponding subjective criterion within that project.

Do not infer enduring taste from one choice or call a model's score a human preference. A prompt-only assignment can be complete without media generation; a media assignment cannot be relabeled prompt-only to hide missing tools. Required unavailable production/inspection tools leave the requested output partial.

## Independence, calibration and comparisons

Track shared generation context, model, verifier code/configuration, test data/source and trust path. Changing reviewer names or taking a majority vote does not make correlated observations independent. Where blind review is required, use separate bounded contexts and the same frozen artifact/rubric, without builder advocacy or other reviewers' answers. Preserve disagreement before synthesis; a concrete mandatory failure survives consensus.

Use positive controls and targeted defects to challenge the evaluator. Headings-only or missing-step artifacts should not pass a completeness gate. Compare the actual runner's aggregation with the reported method; do not substitute a prose claim about its scoring. Keep numeric floors task-specific and disclosed, not copied from a donor.

For reuse audits, compare quality and completed work before speed/cost. Separate selected, comparable and determinate sets. Report unknown measurements and shared account usage honestly. Small, selected or unmatched observations do not support general superiority or a causal learning claim. An approved lesson can remain a useful hypothesis without a measured benefit.

## Final evidence review

Re-read the actual final artifact and current required inputs after all writers finish. Confirm evidence points to those versions and the right target. Re-run affected checks if necessary and still within the contract; if scope or budgets must change, establish a successor rather than editing the old gate. A capture's hashes establish selected-byte identity, not immutable execution throughout or authenticated authorship. State the remaining boundary in the return.
