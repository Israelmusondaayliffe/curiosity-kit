# Grill Me

Use for an explicit full source-first interview: “grill me,” interview me thoroughly, walk this decision tree, or a deliberate Strategy Room interview handoff. A generic critique or small clarification is insufficient activation. Produce shared decision-ready understanding; the interview itself is the deliverable. Read the [common evidence/choice contract](../references/evidence-and-choice.md).

## Frame and inspect

1. Restate the objective, intended decision/deliverable, affected people, known constraints, available evidence and largest unresolved dependency. Correct misunderstandings already resolved in the conversation. A safe working assumption may start the interview, but label it pending.
2. Build a material design tree. Consider outcome/success; audience/stakeholders; scope/exclusions; inputs/source of truth; requirements versus preferences; decisions/tradeoffs; workflow/dependencies; output/quality/review; failure modes/reversibility; ownership/timing/maintenance. Add domain branches only when they could change the result. Connect prerequisites and prune trivia.
3. Before each factual question, inspect the closest plausible authorized source: supplied document, current workspace state or relevant official source. Verify drift-sensitive facts. Record the finding and locator in the working model. Do not ask the user to retrieve a fact you can read; do not search unrelated private material for a source base that was never identified. If sources conflict, show the actual conflict and ask which governs when authority cannot resolve it. If access is missing, name the precise gap.

Separate facts from user-owned values. A source may establish cost; it cannot establish which tradeoff the user prefers. Define consequential ambiguous words before dependent choices use them: “ready,” “simple,” “private,” or “successful” need observable meanings in this task.

## Follow one branch

Select the unresolved prerequisite with greatest effect on the intended outcome. Ask **one to three tightly linked questions per turn**. Explain the consequence only when useful; offer concrete alternatives with tradeoffs and room for another answer. Do not ask downstream implementation questions that the current choice could invalidate.

After an answer:
- Distinguish an observation, constraint, preference, proposal and actual decision.
- Close a branch only when its decision, rationale/governing constraint, dependencies and acceptance test are clear.
- Update a compact ledger of consequential decisions, exact terms, rejected alternatives when useful, and downstream effects. This is not a transcript.
- Add newly material branches. Do not re-ask settled facts/preferences unless new evidence conflicts or the user corrects them.
- If the user does not know, investigate accessible facts first; otherwise offer a reasoned default with its uncertainty and await acceptance. Do not turn silence into consent.

“Relentless” means complete and persistent, never hostile, repetitive or insensitive to a stop. Match depth to stakes, reversibility and cost. If the user wants a shorter exchange, prioritize the highest-impact remaining question and explicitly defer the rest rather than fabricating answers.

## Challenge and converge

When the main branches look settled, pressure-test the actual model: what can fail; which assumption carries the result; boundary/unusual cases; who could disagree/block/misunderstand; expensive-to-reverse choices; ownership/timing/maintenance gaps; and evidence that would show success. Reopen only material weaknesses as branches. A sound plan does not need invented objections.

At useful branch boundaries report four short lines: **Resolved / Assumed (accepted or pending) / Open / Next**. Convergence means goal, deliverable, audience, scope, sources, constraints, dependency order, material tradeoffs/risks, acceptance tests and relevant ownership are clear; contradictions are resolved; remaining assumptions/deferrals are explicit and accepted; and the user confirms the understanding is sufficient. Length alone is not convergence. Stop on explicit user stop, unavailable material access/authority, or confirmed convergence.

## Return

Use this coverage order for the final shared-understanding handoff, combining short items where appropriate:
1. Goal
2. Deliverable or decision
3. Audience and stakeholders
4. Scope and exclusions
5. Decisions and rationale
6. Requirements, constraints and sources of truth
7. Dependencies and sequence
8. Risks and edge cases
9. Success criteria and verification
10. Accepted assumptions and deferred questions
11. Recommended next action

Ask for corrections or confirmation only when convergence is the requested endpoint and it has not already been supplied. Apply actual corrections. An interrupted interview returns its current model and unresolved branch, not a falsely confirmed specification. For Wayfinder handoffs, return only the current branch result and acceptance evidence to the map owner.

Examples of application: a community idea resolves audience/offer before pricing/tactics; a creative brief resolves intended response/message/proof before style; a permissions redesign first inspects the existing policy, then actors/inheritance/migration/failure/audit acceptance. These are method illustrations, not automatic questions or authority to build.
