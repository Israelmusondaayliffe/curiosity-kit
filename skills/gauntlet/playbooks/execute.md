# Execute, inspect and integrate

1. Read the canonical state and verify contract hashes. Confirm actual current capabilities, peer status and approval. Use readiness checks against saved acceptance evidence. Never dispatch a dependent task because a predecessor merely produced files.
2. Reserve a launch before invoking a host helper. The reservation counts against finite runtime caps and declares actor, role, workstream, action, exact write paths, selected model/effort and observed capability snapshot. A replayed request returns may_launch=false. Do not launch again. Unsupported topology or drift stops dispatch.
3. Start the builder with [its local prompt](../roles/builder.md), a fresh bounded input set and exclusive write ownership. Independent writers must have disjoint canonical paths or be serialized. OS locking protects the ledger; it does not sandbox helper filesystem access. Use actual host restrictions where available and inspect returned write sets.
4. Capture a snapshot/hash of the real output and execute every declared inspection. `inspection.py check` captures an authorized argv command, cwd, timeout, exit status and actual output hashes; it is not a sandbox. Native host tools may provide the same evidence. Failed or empty inspection is a failed round, not a critic candidate. Reader proxies and claim audits use the corresponding local tools and prompts. Unchanged bytes may reuse exact still-current evidence, but do not claim another execution occurred.
5. Prepare a neutral pair with `review.py blind`. Give the critic only the packet and frozen criterion. Keep the sealed map outside its input/access scope. Text/PNG sanitation is limited; unsupported formats require an honestly labelled non-blind measured/rubric judgment or a supported neutral render. Do not pass original filenames, metadata, source trees or logs that reveal provenance. The host must establish fresh context and restricted inputs; a script cannot do this by assertion.
6. Collect the [critic](../roles/critic.md) response, complete the recorded host launch, and validate/unseal through the script. The coordinator supplies actual dispatch evidence, not invented IDs. No builder history, inherited turns or reused authoritative critic session is allowed. Record exactly one biggest actionable gap, uncertainty and criterion evidence; an accepted round may record that no material gap remains, and a revise or blocked round never may. Tie/unable is not a win. Low-risk pieces may share a fresh critic only if each retains its own complete verdict and isolation; high-risk work gets individual review.
7. Commit the round record to canonical state before the next, then run `gauntlet.py report` to refresh the local workbench from that state. Replays cannot accumulate wins or reset counters. A rejected result does not disappear from history; diagnose the concrete cause and retry only within remaining budget. Stop/replan when repeated gaps do not improve the target. Reports alone are not progress.
8. At a wave boundary, the lead integrates accepted pieces, resolves or records contradictions and runs affected checks. Use the [smoother](../roles/smoother.md) only for narrow coherence work. Material changes return to their owning workstream. Any changed artifact or predecessor invalidates downstream evidence; recompute hashes and reverify affected outcomes. Record the actual integration command, exit code, evidence and unresolved contradictions. Independent piece success is not whole-project success.
9. When every required outcome and integration check is ready, enter [verification](verify.md). Builders, smoothers and critics never issue the final run verdict.

No helper may change authority, budgets, approvals or the ownership of the final answer. Optional advisor composition uses [the local contract](../references/advisor.md); unavailable optional advice does not disable Gauntlet's own method. A user-requested unavailable extension remains explicitly incomplete.

## Stops and recovery

A budget cap produces exhausted/paused status, not completion. Record missing capability, permission, evidence or conflict with the exact next action. An interrupted reservation is uncertain, not safe to replay. Inspect actual host records and artifact changes, then mark recovery and resume from saved state. Do not reset usage totals or erase failed rounds. Replanning creates a new approved contract and retains previous receipts as history.
