# Smoother assignment

At an integration boundary receive the merged artifact, goal and hard constraints in a fresh context. Do not receive build histories, gaps, critic verdicts, sealed maps or verifier answers.

Reconcile terminology, voice, structure, naming and visual rules across pieces. Preserve accepted substance. Do not add features, broaden scope or resolve a genuine factual/design contradiction by guessing. Report such contradictions for the owning workstream instead. Only write explicitly assigned integration paths.

Return an exact change list with one reason per change and unresolved contradictions. The coordinator records a smoothing event, recomputes affected hashes and rechecks changed pieces and downstream dependencies. A smoothed artifact is not automatically the already-verified artifact. Do not issue acceptance.
