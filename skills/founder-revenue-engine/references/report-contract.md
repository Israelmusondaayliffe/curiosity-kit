# Offline prospect report contract

Use only when a structured standalone HTML prospect report is useful or requested. A short answer, narrative, interview guide or message draft does not need this format. Python 3.9+ standard library only; no installation, credentials, provider calls, JavaScript, external stylesheets or network fetches. This helper reads one supplied JSON file and writes only the requested new HTML file. Clicking a source link later is a reader action.

From this skill directory:

```sh
python3 scripts/revenue_report.py check assets/example-report.json
python3 scripts/revenue_report.py render assets/example-report.json /path/to/new-report.html
```

The output's parent directory must already exist. Output creation is exclusive: an existing file or symlink is rejected, including an input/output collision. There is no overwrite flag. Choose a new filename. Exit 0 means the requested check/render completed; exit 2 means invalid input or an I/O/CLI error, printed to stderr without a traceback. Rendering validates first. A generated file is not proof it was visually checked in a browser or delivered accessibly to the user. Inspect actual output and use the host's supported attachment route.

The [filled synthetic example](../assets/example-report.json) is the canonical input example. No real company, website read, buying signal or outreach is claimed. Existing original report content is retained; formerly duplicated source_title/source_url/source_type/signal_date values move into source records, with dates separated rather than collapsed into an ambiguous signal_date. IDs connect prospects, patterns and sources; opener is a draft, never an execution instruction.

## One bounded schema

Unknown fields and duplicate JSON keys are rejected to prevent silent omission. All listed fields are required unless marked optional. Text is nonempty, at most 20,000 characters per field, and kept in full with HTML escaping and preserved line breaks; null is allowed only where stated. Use honest text such as `Unknown; buyer not confirmed` for missing narrative facts. IDs match `[A-Za-z][A-Za-z0-9_-]{0,63}`. JSON input is at most 1 MiB, UTF-8. Lists have the bounds below; unpaired Unicode surrogates, invalid control characters, nonfinite constants and malformed dates are rejected.

- Report: title, product, target_customer (ICP/job/trigger/disqualifiers), buyer, user, search_scope, generated_at, mode, verdict, window, sources, prospects, watchlist, patterns, outreach_plan, limits. Optional product_url is null or an absolute HTTP(S) URL.
- generated_at: actual report creation date, YYYY-MM-DD, not the historical research cutoff. window: start and end, inclusive YYYY-MM-DD; end is the requested historical evidence cutoff, with start <= end <= generated_at. Do not replace the requested window with a convenient one or invent dates to fit the schema.
- mode: quick (at most 5 qualified prospects), standard (10), deep (20), design-partners (20), b2b (20), community (20). The latter three change research emphasis, not numerical validity or claim status. Ceilings are not quotas. All arrays may be empty except stop_rules and limits. Watchlist: at most 20. Sources: at most 200. Patterns: at most 20.
- Source: id, title, url (HTTP(S) or null), source_type, observed_at (date evidence was obtained, or null if unknown), publication_date (date or null), event_date (date or null), recency_basis (publication/event/unknown), access (read/supplied/snippet/inaccessible), excerpt, limitations. Known observed_at and publication_date must be <= generated_at. When both are known, publication_date <= observed_at. Unknown observed_at stays null and does not prevent a known publication date. Do not invent an observation date for supplied saved evidence. Future event dates may describe announced events but are outside the past requested window. A chosen recency basis needs its corresponding date. Unknown means recency is unknown even if other dates are supplied. Observation is never a substitute for publication/event date. Access labels are supplied metadata, not verified by the tool; supplied is not an independent page read. Do not put unread content in excerpt as though quoted from a read source.
- Prospect (same fields for watchlist): id, name, type, stage, pain_signal, evidence, why_fit, why_now, suggested_channel, opener, caution, dimensions, evidence_ids; optional score. Explain known user/buyer/interview/pilot/payment status in stage. Prospect IDs are unique across both groups. evidence_ids are unique source IDs (at most 200). Qualified entries require at least one referenced read or supplied source. Snippet/inaccessible-only entries must remain watchlist. Watchlist may have no sources. A dated but unread record is still unread, and an undated read record cannot establish current timing. Older/unknown evidence is displayed honestly; deciding whether it justifies qualification is a human semantic review, not a numeric pass.
- dimensions: null means explicitly unscored; in that case score must be absent or null. The report displays `Not scored`, without fabricated zero dimensions. Use this whenever scoring inputs are unknown or scoring is not warranted. Otherwise dimensions contains exactly pain_strength, product_fit, timing, reachability, evidence_quality; each finite numeric 0–5, including fractions, never bool or a numeric string. Score = sum(dimension / 5 × weight), with weights 25/25/20/15/15 respectively, rounded to two decimals. For nonnull dimensions the renderer always recomputes it; the optional supplied score must be numeric if present. A supplied score must match to within 0.000001; it is neither silently clamped nor used as an alternative. Zero dimensions are allowed, but missing dimensions are not silently treated as zero. Score is a ranking heuristic, never a probability; it cannot override missing evidence or a disqualifier.
- Pattern: title, count, insight, prospect_ids, evidence_ids. References are unique and nonempty. count is an integer equal to the number of referenced prospects; evidence_ids must belong to those prospects' linked evidence. Count is the size of this referenced sample, not market prevalence; a single observation is not a repeated pattern. Duplicated underlying sources/prospects still require semantic deduplication.
- outreach_plan: angle, first_step, follow_up, success, stop_rules (1–30 nonempty text entries). State the finite manual plan, measurement window and stop conditions here. No authorization flag or send action exists. Include reply/opt-out handling and do not manufacture a commitment from interest.
- limits: 1–30 nonempty text entries covering evidence/access gaps, assumptions and what still needs direct confirmation.

Source and product links accept only absolute HTTP(S), with host and no credentials, whitespace or backslashes. All user text and link attributes are escaped; source and prospect citations are internal anchors built from restricted IDs. Source records visibly show access, all three dates, recency basis/window result, excerpt and limitations. No automatic sorting invents a confidence claim; preserve the author's reviewed order.

## What a pass means

Checks cover bounded structure, references, numeric consistency and calendar syntax. They do not prove a page was read, a date accurate, a quotation faithful, a claim supported, demand real, a buyer authorized, outreach consented, or legal/privacy compliance satisfied. A hand-authored lie can pass. Review material claims against source contents and distinguish a read source from a snippet or inaccessible page; check source independence and duplicates, relevant timing, disqualifiers, full draft fidelity and stop rules. An honest empty shortlist is a complete outcome. Supplied saved evidence works offline, with access and recency limits visible.
