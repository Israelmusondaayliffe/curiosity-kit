# Sources and adaptation

This package is independently authored from required functions. Its working methods combine Coding Studio and Citizen Forge with substantive Pstack, Gstack, Matt Pocock, Compound Engineering and Ponytail techniques. These sources are more than evaluation labels. No donor implementation engine, personal sibling library, model identity, global configuration, telemetry service or recording upload is a runtime prerequisite.

## Method origins

- [Pstack at df581122](https://github.com/cursor/plugins/tree/df581122cde17e6e27686b5a448bde23e4ad4318/pstack): choose a real verification route before implementation; inspect actual effects; caller-first design and change propagation; preserve behavior during refactoring; identify the bottleneck and compare equal work; record useful lessons. Local homes are plan, implement, debug, refactor, verify, optimize and learn.
- [Matt Pocock at 6fd94792](https://github.com/mattpocock/skills/tree/6fd947921b935b7e1e69293a200400f0fdd5c15f): behavior-driven specifications, vertical slices and dependency-ready work, independent test expectations, reproduction/minimization and original-case replay, deep interfaces/domain types, separate scope and standards reviews, and focused retrospectives. Local homes are plan, implement, debug, refactor, review, learn and language-design.
- [Gstack at c285d88b](https://github.com/garrytan/gstack/tree/c285d88b90d39116ccfa2b901f80ea0fce0b26eb): interface-level acceptance, preserved red/green evidence, input-bound evidence reuse, distinction between defects/advice/missing coverage, delivery obligations, and separate merge/deploy/current-revision health. Local homes are verify, review, deliver, operate and the narrow evidence utility. The donor's ledger, browser runtime, hook, scanner and host generators are not included.
- [Compound Engineering at efcb657d](https://github.com/EveryInc/compound-engineering-plugin/tree/efcb657d9a5733ccc154c36cc7d3d78b4136eb23): proportional planning/review, owned implementation slices, evidence-based recovery, caller-owned completion, exact PR feedback readback, source-grounded discovery, teaching and useful local learning. These inform the local playbooks rather than a second controller.
- [Ponytail at 552acd5e](https://github.com/DietrichGebert/ponytail/tree/552acd5efd0aeae2583a12efe39373d2f076f25e): need-first simplification, adequate project reuse, smallest correct implementation, report-only simplicity review and explicit shortcut limits. The entry uses native-first, simplicity:lite methods. Persistent hook/mode state and benchmark scoreboards are omitted.
- Earlier Codex and Claude Coding Studio and Citizen Forge editions supply the preserved domain functions, control purposes and source-specific failure cases. Source identity does not establish installed-cache parity.

Lauren Tan's Pstack articles, [Part 1](https://x.com/poteto/article/2094457600259842065) and [Part 2](https://x.com/poteto/article/2097732320606507506), inform verification-first and research/prototyping methods. Adapted interpretations are not primary article text, and this attribution does not claim a fresh article read. The local methods preserve project-specific drive/inspect/measure paths, feature maps, empirical prototypes, historical rationale and useful teaching, without importing automatic schedules or forced cloud fleets.

## Deliberate corrections

The local methods retain scope and consent through all retries; separate worker self-checks from required independent acceptance; reject a metadata-only review skip; preserve actual failure instead of changing it to skipped; reconcile uncertain effects before retry; distinguish interface checks from durable-effect proof; and bind relevant comparison/runtime inputs before reusing evidence. Recovery names the state it can actually restore. Missing health observations do not become healthy by default.

The utility computes selected file identity only. It cannot certify a command, reviewer, deployment or user authority. Source-inspired instructions and locally passing checks do not qualify untested host behavior. Optional live tools and external systems need actual availability and appropriate authority.
