# Operate a bounded Midjourney batch

Use this method for requested new jobs, Explore reuse, own-creation reuse, profile inspection, queue monitoring, style discovery, curation, selected HD variations or named recoverable cleanup. Existing complete prompts may be reused directly; prompt architecture is needed only when writing or changing them.

## Establish the requested work

Record the source items or new prompts, submission count, destination folder, selected model, reference/style/profile settings, speed, budget and completion milestone. Distinguish discovery from permission to submit. Distinguish operational selection from creative acceptance. Use the known brief and ask only for a missing choice that changes scope or prevents an action.

Inspect speed and cost before submission. The historical workflow used Relax. Follow the current approved mode and budget; prefer an already-correct session or a supported per-job choice. A persistent mode change that can affect simultaneous user work needs the missing decision. Do not buy Fast time or silently switch to a spending mode. Training personalization and cleanup need their own named scope.

## Use the connected browser safely

Use the permitted browser route for the current host. Source editions cover an in-app browser, the user's connected Chrome session, Claude in Chrome where available, and Computer Use when it supports the needed browser action. Follow the host's connection and delegation rules rather than assuming tools or authentication. State which browser is being used. An unavailable route is a specific blocker, not evidence that jobs ran.

Read [selected Midjourney guidance](../../references/models/midjourney.md) and inspect the live selected model, controls, attachments, folder, active jobs, capacity and notices. The [historical web notes](../references/midjourney-prompt-batching/current-web-operations.md) preserve Explore/Create/profile/queue/speed/Trash behavior. Their observed 10/13 queue counts and old Draft restrictions are not present-day operating limits.

## Submit without losing identity or duplicating work

1. Select one source. On Explore, inspect the image and full prompt before reusing it. For an own creation, retain its job identity and settings. For new work, assemble the complete requested prompt.
2. Copy the exact intended profile or historical code. Preserve every supplied tag, style code, URL and meaningful setting. Inspect the profile if needed; do not replace a historical code with a current default or train a profile as a side effect.
3. Re-observe the composer immediately before entering text. If the user changed it, preserve their input and use a separate safe context or wait. Never overwrite active concurrent work.
4. Verify the complete loaded prompt, references, codes, selected model, folder and mode. Submit one intended job.
5. Observe acceptance through a stable job ID or equivalent unambiguous evidence. Record it. A spinner, copied prompt or changed account total is insufficient. If acceptance is uncertain, inspect queue/history before retrying; do not duplicate a job to resolve uncertainty.
6. Stop new submissions at the requested count or live capacity. A full queue pauses additional work, while accepted work remains active. Check at sensible intervals for the actual mode; latency in Relax is not failure.
7. Track requested, accepted, queued/running, rendered, curated and HD jobs separately. A submission-only task can finish at verified acceptance. Rendering, curation or HD requests continue to those milestones unless blocked or cancelled.
8. Inspect outputs when their stage is requested. Keep the selected image's ID through recommendations, user choices and HD actions. Submit only selected images within the authorized scope, retain parent-image/HD-job lineage and inspect the resulting HD output.
9. For explicitly requested cleanup, resolve exact targets, use recoverable Trash narrowly and verify each change. Report skipped or unresolved targets. Trash is not proof of permanent deletion or privacy erasure.

## Void Style Hunter

Load [the complete supplied recipe](../references/midjourney-prompt-batching/void-style-hunter.md). Its exact starting text is `"" --c 8 --exp 10 --draft --sref random --s 300 --ar`. The ratio is incomplete. Use only the requested or already confirmed ratio; if it is unknown, obtain it before submission.

Keep four stages separately countable:

1. Initial Draft exploration with the completed ratio, exact recipe, selected model and verified live Draft/mode availability.
2. Selected-code Draft reuse. Inspect actual rendered codes, then reuse the full resulting prompts with exact styles/profiles, folder and originating job/image IDs. Repeating `random` is not selected-code reuse.
3. Curation of the resulting images. Recommendations and user choices remain distinguishable.
4. HD variations of the selected image IDs, with each HD job bound to its actual parent and inspected separately.

The source's observed 25 images per Draft run is not a universal guarantee. Count actual outputs and each stage's submissions against its own approved scope. A user may request one stage or the full chain. Stop at that requested stage; do not save a preferred reusable recipe without explicit creative selection.

## Complete or pause with evidence

Keep one compact receipt with source/job/image identity, exact full prompt and settings, acceptance evidence, stage/status, output links or files, selections, HD parent lineage and remaining work. A receipt prevents duplicates; it does not confer creative approval.

Pause dependent actions for changed user input, mismatched prompt/settings, ambiguous source, uncertain acceptance, unsupported requested control, account warning or exhausted budget. Continue already-authorized work when the blocker clears. Report the reached milestone precisely; accepted, rendered and approved mean different things.
