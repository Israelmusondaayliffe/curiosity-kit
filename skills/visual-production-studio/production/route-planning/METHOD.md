# Save a production route when useful

Use for an explicit saved production plan or a complex brief that benefits from recording an owner, supporting methods and intended runtime. This is optional: image/video prompt writing and direct specialist work do not require route JSON. The [work contract](../../references/contract.md) still governs fidelity, permissions and evidence.

1. Extract objective, audience, duration, aspect/dimensions, platform, supplied assets and requested delivery. Identify missing media before generating substitutes. Keep consequential assumptions visible; a draft target size is not a verified platform requirement.
2. Choose one primary owner from the [route reference](references/routing.md). Add only needed support methods. Preserve exact requested model/version independently of this production route. No unspecified model defaults to Seedance.
3. Choose runtime after the deliverable and actual dependencies are known. Retain an explicitly requested engine or existing project dependency. HyperFrames is the inherited authored-motion option where available and appropriate; Remotion remains valid for requested/existing Remotion work. Previs uses prompt-only or external: its source IDs `previs` and `previs-to-sequence` are aliases for the same method.
4. If a saved route is useful, copy [the complete template](assets/route-template.json) into the task workspace and fill its fields. The template is a synthetic example, not a prescribed duration, dimensions or skill sequence. The inherited saved schema uses positive whole-number duration_seconds, width and height; do not round a requested fractional duration to satisfy this optional checker. Keep such a plan in its natural form instead.
5. Run `python3 production/route-planning/scripts/validate_route.py ROUTE.json` from the skill root. Repair reported structure. This reads the selected JSON and prints a result; it does not execute owners, validate model support, prove media readiness or render. Exit 0 means valid structure, 1 means invalid structure and 2 means invocation/read/JSON failure.
6. Load only the selected complete method and its dependencies. End an actual rendered delivery with [delivery QC](../video-delivery-qc/METHOD.md), preserving failed or unrun requirements rather than treating the route pass as delivery acceptance.

If the correct primary owner or requested runtime is materially ambiguous, resolve it before implementation. Previs writes its own Stage 1 prompt and requires inspection of the actual board before Stage 2; the route record cannot replace that handoff.
