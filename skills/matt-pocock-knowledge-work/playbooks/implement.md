# Implement

Read the [host contract](../references/host-contract.md) before first repository access or action. This playbook runs only inside an explicitly selected Matt family workflow; source commands are not permission.

Execute one approved, unblocked observable-result slice from the spec, ticket, or settled small-task conversation. Inspect the closest project instructions and source artifacts; state the slice, blockers, allowed paths and acceptance checks, and refresh live state rather than trusting a stale handoff.

If the user passes a ticket reference, fetch it from the issue tracker and state its title before starting. If the reference is ambiguous, ask.

For software, read and apply [tdd](tdd.md) where appropriate at pre-agreed seams. Missing consequential seam approval is a blocker; do not repeat an already settled seam interview.

Run typechecking regularly, single test files regularly, and the full test suite once at the end.

Once software work is done, read and apply [code-review](code-review.md) to the actual scoped candidate, including staged, unstaged and new source. Repair findings only within the execution authority, then rerun affected checks; keep Standards and Spec axes distinct.

If the task authorizes a commit, commit only owned changes to the current branch after verification. Otherwise report the prepared change. Never blanket-stage, push, open a PR, assign, close tickets or mark their acceptance boxes as a side effect of this method.

## Knowledge-work execution

Preserve source-to-claim evidence and distinguish verified facts, inferences and missing evidence. Make the smallest complete change producing the slice's observable result. After meaningful changes, run the narrowest useful evidence or artifact check; repair failures before adding scope. Inspect the actual rendered/document/application surface using available tools, not merely its source text. Review both evidence quality and compliance with the originating brief: audience, use, requirements, exclusions and delivery constraints. If a renderer or source is unavailable, identify the unverified criterion without claiming completion.

## Mixed-work verification and closeout

Keep one acceptance surface and run both relevant software and knowledge-work checks. At completion, rerun final checks, compare the result to the approved spec, and return the artifact/change, fresh evidence, remaining risks and next unblocked slice. A passing code test does not prove a factual claim, and a sourced claim does not prove working code.
