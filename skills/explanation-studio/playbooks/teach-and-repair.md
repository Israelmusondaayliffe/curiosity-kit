# Repair confusion or teach one concept

Use for a failed explanation, a misconception, a requested understanding check or one bounded learning interaction. Ordinary explanation remains direct. Full multi-session course state belongs to a separately requested learning workflow.

## Find the smallest gap

When the reader says the explanation did not land, do not repeat it with synonyms. Identify which link is missing: an unfamiliar term, a prerequisite, a wrong relationship, too many simultaneous steps, a mismatch with the source, or an unsuitable representation.

Use their actual words and prior attempt. If the gap is clear, explain it immediately. Otherwise ask one small diagnostic question or invite a short attempt. Avoid a background interview. Never infer confusion or mastery solely from response length.

Restate enough context to make the answer usable: what the thing is, what problem the current step addresses and how it connects to what came before. Use an existing supplied glossary where relevant; do not search unrelated files or create a mandatory glossary system.

Change the example, show a smaller case, contrast expected and actual behavior, or use a picture that exposes the missing relationship. Keep the same facts and uncertainty. Ask another question only if its answer will change the next teaching move.

## If practice is requested

Set one observable outcome, such as “predict whether this request can be retried,” rather than “understand retries.” Respect the learner's sources and constraints. Use the smallest useful sequence:

1. Establish the starting point from a short attempt or available context.
2. Explain the missing concept and, if needed, work one example.
3. Give a similar task that requires the learner to use the idea.
4. Wait for their real answer. Check it against the source or worked solution.
5. Say what is right, identify the exact mistake and give the next useful hint or correction.
6. Try a different example without the earlier support when transfer is the goal.

Use the least help that permits progress: a directional hint, a targeted cue, a partial step, then a full explanation or solution when requested or needed. Do not withhold an answer to obey a rigid teaching persona. When repeated attempts fail or frustration rises, give more explicit help and change the representation.

Choose a question that distinguishes real understanding from repeating a phrase. Application, prediction, explaining a contrast, or finding a boundary often works better than vocabulary recall. Plausible multiple-choice alternatives should not reveal the answer through length or formatting; equal character counts are not a requirement.

## Prediction before reveal

If the user explicitly chooses prediction-based practice on a change, show the raw change or neutral input before interpretation. Ask what they predict and stop for the answer. Do not put the explanation immediately below the question in the same message. After the answer arrives, compare it with the actual behavior and identify the gap.

If the user wants only the explanation, skip prediction and exercises. A declined check stays declined. In a noninteractive run, deliver the explanation and optionally an unsolved self-check with its answer clearly separated when requested. Do not manufacture a learner response or mark mastery.

## Example of specific feedback

Source: retries are permitted only when `retry_safe` is true; a timeout does not prove a write failed.

Learner: “A timeout means the write failed, so we should retry.”

Useful feedback: “The timeout tells us the response did not arrive in time. The write may still have succeeded. Check `retry_safe` before retrying. What can you conclude if it is false?”

If the learner remains stuck, state the answer: “Do not retry under this rule. The effect of the first write is still unknown.” Then use a new case. Do not merely say “try again” or praise the wrong causal assumption.

## End at an honest outcome

An accurate application supports understanding of that tested concept under those conditions. It does not prove long-term retention or competence in every related task. “I understand” is a conversational signal, not a test result. Use terms such as ready for this next step, another attempt would help, or this part needs a new explanation only when actual evidence supports them.

Do not create persistent learner records, schedules, mission files or community contacts from a single explanation request. If sustained teaching is explicitly requested, preserve its goals and existing records through a suitable authorized owner. This local method can still explain one concept without that owner installed.

Return the explanation, correction or feedback itself. If the learner stops or changes mode, follow their lead. The goal is the missing understanding, not completing a ritual.
