# Selectable work records

Use only the sections the task needs, in the user's existing format or one compact working note. Bracketed prompts below are template fields, not completed evidence. Replace or omit them before delivering a filled record. A short answer can hold the same information inline. Do not create six files because six templates are available.

## Work brief

- Task identity and current request: [stable description or supplied ID; governing instruction]
- Outcome: [actual artifact and what the reader can decide/do]
- Reader and known concepts: [known facts; do not invent]
- Required questions/sections: [complete list of obligations]
- Included / excluded scope: [boundaries]
- Sources of truth and allowed source set: [locations/owners; missing access]
- Dates or versions: [relevant event/effective/publication bounds; freshness need]
- Format, length, destination and protected material: [binding requirements]
- Authority: [what may be done; what is only recommended or drafted]
- Success checks: [observable evidence for each required outcome]
- Open points: [discoverable fact / ready decision / blocked prerequisite / expert knowledge / safe assumption]

## Source record

| Source ID | Title / owner | Exact location and relevant passage | Type / origin chain | Dates | Actual access/read extent | Relevance and limits |
|---|---|---|---|---|---|---|
| [S1] | [title, source owner] | [URL/file/connector reference, section/row] | [primary/secondary/discovery; repeated origin IDs if known] | [publication/update/effective if known; actual access separately] | [read portion/full/supplied excerpt/inaccessible and reason] | [question, definitions/population, conflicts/corrections] |

Do not supply a guessed date or claim to have read an unavailable page. Distinguish discovery from direct evidence. Record clause-level supersession with the authority/effective date and which claims changed, not a blanket deletion of the older source. A null search result describes the actual searched scope only.

For a recommendation: [decision, factual premises, connecting assumptions, credible alternatives, costs/risks, reversibility, what would change the decision]. Mark recommendations as judgment; they are not approved actions.

For a quantity: [inputs, units, population, numerator/denominator, window, exclusions, formula/tool, actual result and rounding].

For chat answers, small tasks and ordinary file drafts these human-readable fields are enough. When a file deliverable requires a traceable evidence record, use [the evidence contract](../references/evidence-contract.md) and [filled JSON example](evidence-example.json), with actual task data and honest review state. The example is not a passed review.
