# Line edit, simplify and remove revision tracks

Select the requested operation. Read active voice/style guidance and original text. Protect exact material and citation relationships. In diagnosis, return located findings; in revision, deliver the complete revised passage first. Explanations and change summaries are optional unless requested.

## Line edit

Work on sentence meaning, architecture, cadence and diction once the needed structure is stable. Look for backtracking syntax, weak or inflated verbs, vague nouns, redundant softening, unsupported intensifiers, throat-clearing, repeated points, unclear references and unnecessary jargon. Prefer active voice when the actor matters; passive can correctly background an unknown or irrelevant actor. Sentence length, fragments and punctuation follow thought and evidenced voice, not a universal short-sentence rule.

Compare every change with the original proposition and certainty. Do not cut a necessary “may,” remove a technical distinction, detach a citation or make a personal observation universal. Preserve humor, deliberate repetition, priors, asides and useful weirdness when they carry the writer. Perform source-aware Unslop before chasing isolated words; [Unslop](unslop.md) owns that method. Do not run a second full cleanup lifecycle from here.

For material edits, a short before/problem/change list helps the writer revert individual changes by number or description. Do not print every punctuation change or add a mandatory final-pass offer. Keep the original version for a requested revert.

## Simplify

First state privately what the source actually means, including conditions and limits. Replace jargon with plain equivalents or define a necessary term on first use. Turn nominalizations into actions, unpack nested clauses, make relationships explicit and place the point where the reader needs it. A supported example or clearly labeled hypothetical can make abstraction concrete; never insert invented statistics as an apparent fact.

Preserve precision, nuance, voice and warranted uncertainty. If a shorter replacement changes mechanism or scope, keep the precise term and explain it. A complex idea can require several clear sentences; simplification is not a word-reduction target or childish tone. Return usable text with only a useful note about substantive changes.

## Tracks: revision residue

Check for transitions to removed sections, rebuttals whose target disappeared, duplicated explanations, references to missing examples, an obsolete drafting question and warm-up that no longer serves the opening. Distinguish the writer's discovery process as evidence or narrative from drafting chatter. Remove hedge accumulation only when it adds no actual uncertainty.

For each proposed cut ask what the reader loses: evidence, orientation, voice, necessary explanation or meaningful discovery can justify keeping it. Do not strip all first-person process to make writing tidy. Repair broken continuity, then inspect surrounding sentences once.

## Finish

Use `wlm.py protect BEFORE AFTER` for substantial prose-file edits; explicitly selected exact prompt/legal blocks may be supplied with --exact. Ambiguity is a manual-review requirement, not permission to transform the whole file. A passing textual check does not validate facts or code semantics. Restore damaged exact material from the actual baseline. Stop repeated polish when it no longer improves the requested result and return to the parent workflow.
