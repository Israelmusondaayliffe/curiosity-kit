# Continuity Vault

Return a useful artifact that another reader can use without guessing what happened or which source to trust. Work from the selected project, records and intended next use. Preserve substantive methods, exact decisions and evidence. A completed handoff is not a claim that its unfinished underlying task is complete.

Read [the source and authority contract](references/source-contract.md). Use the host's actual loaded entry and native tools; inspect relevant project instructions and current changes. Resolve only material uncertainty. An already settled brief does not need another interview.

## Choose the requested result

| Result | Local method | Delivered work |
|---|---|---|
| Handoff, pause record or resume orientation | [Handoff and resume](playbooks/handoff.md) | Current source-linked task state, decisions, actual proof, gaps and next permitted action |
| Reusable insights, five extraction moves or promotion | [Extract and promote](playbooks/extract-promote.md) | Complete useful notes, procedure or proposed destination decision |
| Outputs from a completed meeting, workshop or interview | [Session outputs](playbooks/session.md) | The selected permitted artifacts, faithful extraction and explicit blocked contributions |
| Find prior evidence or digest a selected corpus | [Search and digest](playbooks/search-digest.md) | A supported answer or complete digest with actual retrieval coverage |
| Check stale, conflicting or unreliable knowledge | [Trust audit](playbooks/trust-audit.md) | Claim-specific findings, scope, evidence and clearing actions; sources unchanged |
| Explain relationships or build/query/update a graph | [Relationships](playbooks/relationships.md) | A source-backed small map or actual provider-backed result, with provenance and limits |

Load only the selected method and its required references. Follow links needed for the actual task; an index is not the method. A missing optional collaborator does not remove local expertise. A missing source or provider blocks the affected claim or operation, not unrelated usable work.

## Work with evidence

1. Name the source set, purpose, receiver or audience, current task authority and allowed writes. Reuse the scope already given. Do not silently broaden a project, time range or source search.
2. Read the actual load-bearing material. Keep source text, attributed decision, observation, inference, proposal and newly authored derivative distinct. A summary can guide retrieval but cannot establish an omitted approval, cancellation or event.
3. Preserve exact quantities, units, ordering, exclusions, conditional exceptions and rejected alternatives that matter to reuse. Inspect an ambiguous short answer beside its question and recommendation. Never invent a decision to make a handoff look complete.
4. Keep source observation time separate from the date a digest or worker report arrived. Repeated reports of one event remain one evidence chain. Keep current accepted state separate from stale or delayed contributions.
5. Revalidate what changed or carries a consequential claim. Preserve unchanged valid proof with its original scope. A new summary date, matching subset of files or multiple agreeing reviewers cannot make old evidence current.
6. Produce the requested full artifact. A recommendation list, routing record or validator output is not the requested digest, note, session derivative or handoff. Preserve source pointers and material unknowns in the delivered result.
7. Read back an authorized saved artifact and check the links needed by its receiver. Distinguish local creation from accessible delivery. Repair and recheck a concrete defect within the task's agreed scope and bounds; otherwise report the remaining gap and its next action.

## Exact checks when useful

The optional [record checker](references/record-checks.md) catches inconsistent selected session records and trust-audit statuses. It reads one explicit JSON file and changes nothing. A structurally valid blocked record is a valid result. Exit zero never proves consent, semantic support, source completeness or actual creation.

The locally packaged [evidence helper](references/evidence-cli.md) snapshots and compares explicitly selected file bytes and supplied context. Use it when a later reader needs an exact input identity. It does not discover all dependencies, authenticate a writer, run a command or judge the outcome. Neither helper is mandatory for an ordinary prose answer.

The [handoff form](assets/handoff.md) is optional. Start with an existing suitable project format instead of manufacturing records for a one-step task.

## Independence, cooperation and stop

Memory can provide authorized recall or working-state inputs, but its engine is not required. Coding Studio keeps its own coding learning methods. Strategy Room owns substantive decision interviews/maps; Practice Compiler owns repeated-practice mining. This skill owns general continuity artifacts and the complete local session-compounding method. Accept bounded inputs through supported interfaces without reading a sibling's private implementation or assuming it is installed.

Use a fresh supported reader for an important cold-read check when useful and permitted. Give the actual artifact, intended next task, allowed sources and expected result. Inspect its returned work. If only self-review is available, label it. A role label or second method call is not an independent reader. Preserve inherited authority and explicit model selection; otherwise choose a capable available model suited to the tools and work. No fixed model, mandatory worker fleet or new scheduler is required.

Stop when the requested artifact and relevant checks are complete, the user stops, the agreed bound is reached, or required authority/source/tool access is missing. Give the actual result, what was checked, what remains unknown or blocked and the smallest next step. Do not retire a source capability, install a provider, start a watch, promote global instructions or publish externally as an incidental part of continuity work.
