# Research a recent question

Use this method for a fresh public or supplied-evidence question. Start saved-artifact requests with [library-corpus.md](library-corpus.md). Read [the evidence contract](../references/evidence-contract.md) before collecting or judging claims. It owns record fields, date eligibility, source lineage, claim support and privacy. Use only the source profiles needed for this question.

## Establish what would answer the question

1. Keep the user's original question and constraints intact. Identify the outcome: explain developments, assess a claim, recommend a fit, compare alternatives, discover candidates, or inspect hiring signals. Use [comparison-discovery.md](comparison-discovery.md) or [hiring.md](hiring.md) for those specialized decisions. Do not interpret every slash, URL or multiword topic as a comparison.
2. Resolve the subject through official links, identifiers and relevant context. Separate person, employer, product, project and category. Check the organization/domain behind an account, and a GitHub account's person/organization type. A frequently returned handle or verification badge is only a lead. If two plausible identities would change the answer, ask the smallest necessary question; otherwise state the resolved scope.
3. Set absolute start/end dates, timezone and boundary convention under the evidence contract. Use the requested historical/as-of interval when supplied. Quick/deep effort never changes the interval. Decide whether the question concerns publications, discussion, events, releases or a current snapshot. A recent announcement of next month's event supports an announcement, not an event already held.
4. Separate retrieval terms from ranking criteria. In "ten useful tools for solo designers," ten is an output limit, not an entity keyword. Preserve demographic, numeric, geography, version and tutorial constraints in the decision criteria even if a short search omits them. For ambiguous everyday-word brands, add a verified domain/category anchor. For "how to" wording, search the underlying technique as well as the phrase. Preserve original-language names and useful transliterations; multilingual research has no mandatory provider.
5. Check available native search, connected read tools, permitted browser and supplied evidence via [host-contract.md](../references/host-contract.md). A public question does not authorize scanning personal files or accounts. An explicitly selected private corpus stays a separate local lane; do not send its names, excerpts or inferred queries to public search without applicable authority.

## Make a small collection plan

Write task-local research questions that could change the answer: what happened, what supports it, who disagrees, and for whom it matters. For each material question, name the useful source lane, an initial query and a follow-up trigger. Select from:

- [Primary sources](../references/source-primary.md) for official changes, original research, repositories, verified boards and exact read-only market observations.
- [Community sources](../references/source-community.md) for practitioner experience, dedicated and broader discussion, author/mention lanes and reviews.
- [Media sources](../references/source-media.md) for original reporting, newsletters, videos, creator posts, transcripts and their discussion.

Treat each explicitly requested source as required unless the user relaxes it. Attempt its permitted route or identify the exact blocker. Optional breadth depends on the question, not a fixed source checklist. Quick work narrows optional branches and reads the best-supported relevant items. Deep work follows important contradictions, primary references, comments/transcripts and missing perspectives further. Set sensible search/read attempt and time budgets for the task; count failed attempts too. Do not promise a collector volume, exhaustive platform access or a successful-read quota before observing it.

For substantial parallel work, assign disjoint lanes with the same entity, window, questions and privacy scope. Request exact item links, body-backed observations, read coverage, contradictions and unresolved leads. Merge centrally. Several workers repeating one announcement are still one origin.

## Collect and read

1. Run the initial source-appropriate queries. Record the actual query, route, retrieval time and lane outcome. Distinguish a successful empty search from inaccessible, denied, failed, truncated or skipped collection. A search result is a candidate, not a fully read source.
2. Validate subject and date before enrichment. Reject namesakes and known out-of-window publications from the recent set. Keep useful older context and undated leads separately. If a result says "updated," find the original date or retain the uncertainty. Exclude an impossible/future publication timestamp from completed recent evidence; do not stamp it with retrieval time.
3. Open the original body for each material candidate. Follow an article's link to the underlying release, study or discussion. Read enough before and after the relevant passage to preserve qualifications, speaker and meaning. Capture exact locators and available body/excerpt provenance under the evidence contract. Mark a targeted read as targeted. A snippet, generated answer or inaccessible body cannot silently support a stronger claim.
4. Enrich based on question relevance and evidence gaps. Read replies when they clarify an experience or dispute it; read the relevant transcript segments before attributing spoken claims. Preserve truncation, language/translation and missing sections. Prefer full permitted context over a copied collector's character cutoff. If the body is blocked, use another permitted source or supplied evidence and keep the original gap; do not bypass the access restriction.
5. Deduplicate exact items, then identify shared-origin stories and cross-posts. Retain genuine independent observations even if they disagree. Keep the original source and useful later reporting when the latter adds distinct evidence. A syndicated rewrite without new reporting adds reach, not corroboration.
6. Maintain the claim ledger as collection proceeds. Separate what a source explicitly states, what independent evidence supports, what you infer and what remains unknown. Include contrary evidence beside the claim it challenges. Do not wait until prose drafting to discover that a central conclusion has no readable source.

## Choose what matters

First apply entity, period and task eligibility. Then select by direct relevance, specificity, readable evidence, independence, useful contrary information and fit to the user's constraints. Keep a low-engagement original report if it answers the question better than a popular repost. A first-party statement establishes what its author announced; its performance or impact claims may still need independent checking.

Within a source, observed engagement can help choose which discussion to inspect. Preserve metric type, observation time and unknown versus zero. Never sum incomparable likes, views, votes and comments into factual confidence. If a requested ranking uses explicit comparable input ranks, disclose the input, weights and limits; otherwise give qualitative reasons rather than an invented score. Keep counts tied to the actual deduplicated sample and source coverage.

Group evidence into themes only after reading. Give each theme a representative original item, supporting or contrary observations, and a bounded interpretation. Make cross-theme conclusions after checking overlap, so one prolific author or repeated campaign does not become a market-wide trend. For recommendations, state who the option fits, the supported reason, the tradeoff and the evidence gap. "Most mentioned in this sample" is a separate descriptive result, not "best."

## Close material gaps, then answer

For each unresolved question, choose the next action that could change the answer. Follow a cited primary record, search a contrary formulation, repair an ambiguous query, inspect a broader community, or check the exact version/datum. Record a substantive reframe instead of repeating failed keyword searches. Do not expand the date window or source permissions to fill an empty result.

Stop ordinary research when the material questions have adequate support for the stated conclusion, or a named evidence/access/permission limit prevents further useful progress. More duplicate URLs are not progress. A user-requested continuing monitor has its own stopping condition and goes to [watch-brief.md](watch-brief.md).

Deliver the answer in the requested register and length. Include exact source links near material claims, the period/as-of basis, consequential disagreement and the coverage limit that changes interpretation. A short answer can contain one clear conclusion and one decisive caveat. A deep report may need themes, comparisons and a source ledger, but depth does not mandate a long report. Return a useful partial or no-conclusion result when appropriate.

Before delivery, inspect the actual answer against its sources: all requested parts addressed; dates mean what the prose says; counts and denominators match; origin copies do not inflate independence; quotes are accurate and within applicable limits; private evidence remains private. If saving/exporting was requested, use the actual local record contract and [export.md](export.md); a valid JSON file does not certify source truth. No store, scheduler or external publication is implied by finishing research.
