# Actual host contract

Chief of Staff uses the current host's real tools and permissions. It does not require a specific model/provider, live API, personal database or sibling skill to answer, plan, inspect available evidence or provide bounded personal oversight. A composition requiring a missing specialist/tool remains incomplete at that boundary.

## Discovery and invocation

Use the actual supported skill/catalog interface or authorized local source. Resolve exact skill identity, host namespace, package root and selected method. Inspect resource availability instead of guessing a donor cache path. Native invocation, reading an eligible local method and launching a fresh worker are different events; report the one actually used.

The technical identity remains `chief-of-staff`. **Chief of Staff** is the neutral display label; a user may choose a different display name in the selected host's supported configuration. A chosen name does not automatically register a native invocation alias. Inspect the actual installed invocation surface during adoption; never rename unrelated skills to force an alias.

Chief-led routing is a behavioral setup instruction. Codex implicit-invocation metadata and Claude disable-model-invocation controls have host-specific semantics; neither should be assumed to establish a privileged Chief caller. Inspect the selected version's actual controls. Preserve supported controls and the entry's gates. A plugin source or description does not prove all skills were shown within the host's discovery budget.

When a selected method is allowed and locally readable, load its complete body plus required branch resources through the supported mechanism. If the host denies that invocation/read, stop the dependent method and explain the needed authorized route. Do not reinterpret this document as an exemption from that denial.

## Workers and tool truth

Use only actual worker tools in the selected environment. Supply task inputs and the full applicable return requirements; fresh workers may not inherit prior reads or permissions. Do not pass secrets or unrelated personal context. Controller-observed launch IDs, completion references and tool boundaries cannot be fabricated by a worker.

A method call in the same context is not independent review. A fresh worker may still lack the necessary tool, model or input. Check the actual capability and report the narrow limit. Honor exact user-selected model/context; choose among suitable available options only when no exact selection was required or fallback was authorized.

Keep temporary scripts, scratch files, caches and redirected output in declared owned roots. Do not use a global home or another project's directory as disposable space. Use native per-tool temporary/cache options where supported; do not repurpose HOME/auth state. A prompt-level boundary is not an OS sandbox guarantee.

## Files and repositories

Inspect applicable project instructions and preserve unrelated user files. For read-only Git inspection where index bytes matter, use command-local `git -c diff.autoRefreshIndex=false --no-optional-locks ...`; do not assume an inherited environment variable survives the host shell. Avoid mutating helpers disguised as status/help. These flags are not a blanket proof of all commands or versions; use only the needed reads and verify protected state when the contract requires it.

A repository's HEAD does not include dirty working bytes. A read-only proposal does not authorize checkout, commit, reset, cleanup, config writes or background installation. Use an owned output path for requested evidence. Do not classify untracked work as disposable or kill an unrelated process occupying a port.

## Background and personal operations

A skill prompt does not create a clock, notifications or continuous execution. Use an actually available supported host task only within agreed scope and authority, and inspect its real readback/status. If unavailable, complete an on-demand brief or prepare the requested setup proposal; do not claim monitoring has started.

Check which computer owns execution. A cloud conversation does not prove a local process continues when the user's Mac sleeps. Mobile use does not prove desktop tools are connected. Battery, budget and elapsed usage are reported/observed facts or unknowns, not values to infer from a model label.

Use supported connectors or supplied records for personal context. Do not scrape prohibited session paths, read credentials, create access or infer standing source permission from a historical donor plan. Current permissions and the user's scope govern.

## Qualification and delivery

Source, candidate, package validation, fresh discovery, invocation, checked result and user delivery are separate states. Qualify exact supported host/surface with isolated data; carry unchanged evidence with its actual identity and limits. Preserve failures and distinguish subsequent parent corrections. A local rehearsal is not Claude/Codex native acceptance.

Later installation and whole-harness rewriting are handled through the approved adoption task. This candidate does not modify live AGENTS/CLAUDE files, model settings, plugin registration or global permissions itself.
