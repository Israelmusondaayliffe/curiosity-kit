# Personal oversight

Help with agreed commitments, deadlines, planning the day, follow-ups and useful opportunities. The [entry](../SKILL.md) owns permission, the life-plan exclusion and how to handle an acknowledged concern. This method works without another skill, a personal database or a standing scheduler. Use only relevant authorized sources and actual host capabilities.

## Choose the useful operation

A direct request selects its operation. For proactive attention, first establish that the responsibility and notification destination are already agreed, the fact is current and the interruption helps. Source access alone does not make every topic an ongoing responsibility. Never infer a medical condition or failing relationship from one distracted week.

Use the smallest operation that helps: prepare a concrete next action; give a bounded brief; show changes since a comparable observation; review actual work over a selected period; or prepare an opportunity/content item. Combine them when the user needs one cohesive result, without producing duplicate reports. Durable state is needed only for comparison, follow-up, repeated work or interruption; [Personal state](../references/personal-state.md) owns its format, persistence and delivery rules.

## Prepare a next action

1. Find the actual commitment and source. Confirm who owns it, what outcome remains and the deadline or explicit unknown. A reported commitment and a request from somebody else have different authority.
2. Separate completed work, current progress, external waiting and blockers. Opening a page, drafting a message or receiving a reminder is not completion. Use an observed result or the user's completion report, with attribution.
3. Find the smallest useful step that moves the outcome: a source-linked answer, prepared document, exact next click, bounded research gap or a decision with a recommendation. Do that authorized preparation rather than repeatedly telling the user to act.
4. Rank by real consequence, verified timing and the user's current priorities. A date without timezone or a phrase like “Friday” may need clarification before acting as a deadline. Do not invent availability from an empty calendar block.
5. Present the useful material and one clear next action. If the next step needs a decision or permission, say exactly which one. Keep sensitive case details out of a general reminder; retain the milestone and useful source link.

## Give a bounded morning or day brief

Establish the date/timezone, sources and relevant window. Read a prior baseline only if this is a continuing brief. Fetch the minimum current source data, including enough event/invitation detail to notice a changed time, location, cancellation or reply request. Record actual coverage and failed reads. A bounded calendar/mail query is not the whole inbox or the whole day.

Classify relevant items as urgent, needs-action, waiting, informational or completed. Lead with high-consequence action, then time-bound commitments and important discrepancies. Check whether an invitation is actually accepted, declined, tentative or unresolved; do not turn a received invite into a confirmed appointment. Mention a clash only when actual times overlap and distinguish travel/transition assumptions from observed constraints.

Choose a feasible short set of priorities, not a fixed quota. Include source links and the concrete next step. Use known capacity or ask if it changes the proposed plan. Briefly label a missing source whose absence could change the recommendation. Quiet sources do not prove there is nothing to do.

If persistence is appropriate, save the observation independently of sending the brief. Follow the delivery rule in Personal state. For an on-demand brief, “No material changes in the sources checked” is a useful result. For background observation, suppress a notification that has no useful update unless an agreed reminder is due. Neither path fabricates new priorities to fill a template.

## Compare follow-up changes

Compare the same responsibility, source/account, query/window semantics and baseline schema. If coverage changed, describe the difference rather than claiming a clean delta. Use stable source IDs before content similarity. Two different items with identical text are still two items.

Compare material fields: action requested, owner, status, due time/timezone, event start/end, location, attendees/response state, cancellation, relevant subject/body revision, blockers and source-confirmed completion. Normalize ordering where order has no meaning. A changing observation timestamp is not itself a new obligation. A near deadline may increase urgency even when the source body has not changed; tie that judgment to the real current time.

Distinguish new, changed, resolved and unchanged. State why an item changed and what the user should do differently. Do not call an item resolved merely because it is absent from a page, a partial query, a changed window or a failed connector. Keep unresolved items with dated last-known information until source evidence or the user settles them. Preserve unread page/cursor gaps instead of advancing beyond them.

Save a comparable new observation even if nothing changed when ongoing comparison requires it. A previously failed notification still needs settlement; do not suppress it because its content matches a saved brief. Preserve the difference between source change, increased urgency and reminder delivery.

## Review a selected week of work

Agree the period/timezone and use supported, authorized task history or supplied artifacts. Count root user outcomes, not every child message, tool call or duplicate draft. For each substantive result, identify actual final artifact/version and scope: verified/delivered, in progress, blocked or proposed. Distinguish production from acceptance and publication.

Look for material changed outputs, repeated blockers, commitments awaiting the user or another person, and the next useful action. Reuse evidence already bound to the final result. A different task count is not necessarily more useful work. Note inaccessible periods or missing artifacts explicitly; do not mark the entire week reviewed from a small lookback. Never inspect prohibited session files to fill coverage.

Give a concise account of what moved, what needs attention and the next priorities. This is a work review, not a life-plan scorecard or automatic schedule. Recommend a reusable improvement only when actual repeated evidence makes it worth considering. Do not create a new skill, policy or memory feed as a side effect.

## Surface opportunities and prepare material

Tie an opportunity to a current agreed interest or responsibility and dated evidence: a relevant partnership, client request, content opening, application or useful reusable asset. Check whether the user already handled it, declined it or has a matching item queued. Do not repeatedly relabel the same opportunity as new.

Prepare the smallest useful artifact: source-linked summary, draft response, content outline or concrete next step. Use the relevant domain specialist for substantial craft when available and eligible; a simple draft can be completed here. Record intended audience/destination when a later external action is involved. Private context is background for judgment, not content to copy into a public draft or worker prompt.

Keep proposed, drafted, ready for review, approved, scheduled and published distinct. An edit to approved content changes what is approved; preserve exact final body/assets and the scope of the user's permission before any separately authorized effect. Check the actual destination for duplicates and read back a real effect. The common uncertain-effect procedure is in [Resume](resume.md).

## Keep attention useful

A nudge should have a reason: consequential deadline, somebody waiting, meaningful new information, rising cost, missing required proof or a useful simpler route. Offer the next action or recommendation, not guilt. Use current evidence before repeating an old concern. The user's decision to continue can be reasonable even when the work is demanding.

If repeated delivered reminders go unanswered, ease off and offer a smaller prepared action or a different approach. Follow the agreed reminder cadence rather than escalating pressure; a failed delivery is not an unanswered reminder.

Do not demand a pause solely because a project is large or the user is enthusiastic. Compare the next effort with the useful remaining outcome; do not justify further waste only by past investment or use sunk effort as a reason to abandon a still-needed result. Preserve requested quality and the user's leadership.

## Optional ongoing operation

Only establish an ongoing program when the user has requested its responsibility, bounded source scope, useful notification destination and stopping terms, and the host actually supports it. Confirm missing consequential details. Use the host's native task/scheduler when appropriate; do not build a daemon because a prompt cannot wake itself. Observe the created configuration/readback before saying it is active.

Record timezone, occurrence identity, applicable budget/expiry and pause/stop behavior. Recheck current authorization and expiry before source work and consequential effects. Avoid overlapping occurrences; preserve pending work rather than delete it to free a quota. A stopped or expired program must suppress queued unsolicited work. If native cancellation cannot be verified, report that exact uncertainty instead of promising it stopped.

Paused proactive oversight does not cancel a fresh direct request. Resume only the intended scope after checking actual in-flight effects and stale sources. No historical pilot dates, model choices, whole-mailbox grants or life-plan review cadence become defaults.
