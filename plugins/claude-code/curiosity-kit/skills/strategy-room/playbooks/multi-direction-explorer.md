# Multi-Direction Explorer

Use to generate genuinely different options, angles, names, concepts, prompts, creative directions or strategy paths, or to narrow an existing set. Read the [common evidence/choice contract](../references/evidence-and-choice.md) and [variation/selection reference](../references/variation-and-selection.md). Use the [options matrix](../assets/options-matrix.md) when it helps comparison.

## Generate

Establish the seed, desired outcome/audience, fixed constraints, requested breadth and whether the user wants generation, selection or both. Preserve a supplied candidate set when selection is the task. Select meaningful variation axes: audience, business goal, format, medium, tone, risk, visual language, technical mechanism or degree of customization. Name which properties must remain fixed.

Generate complete candidate directions, not synonyms. Each gets a stable label, governing idea/mechanism, intended audience/context, why it might work, distinct benefit, cost/risk and a specific use/example. Honor an exact requested count. Broad exploration can retain ten or more distinct directions; do not impose ten on an explicit two-option request. If constraints genuinely admit fewer viable mechanisms, explain the limit and distinguish infeasible explorations instead of padding.

Audit pairs for meaningful difference: would they lead to a different artifact, behavior, audience, tradeoff or test? Merge redundant variants while preserving real differences, then replace only if the request needs more valid options. A bullet count cannot make repeated ideas diverse. Do not generate images, build prototypes or launch candidate workers automatically.

## Select

When requested, compare eligible options against the same visible goals, hard constraints and preferences. Explain evidence and unknowns; distinguish promising from demonstrated. Recommend the strongest two or three for a broad shortlist, or the user's requested number, with why each earns its place and what would change the ranking. If preferences could reverse the result, ask the one governing question rather than inventing weights. A request for options alone need not force a winner.

Only combine directions if the user asks for synthesis: choose a named base, identify specific compatible elements from others, state what is retained/rejected, then recheck constraints and distinctness. An automatic “best of everything” hybrid hides tradeoffs and can bypass the user's choice.

## Return and stop

Return the requested options with their differentiating logic, shared comparison, selected shortlist if requested, tradeoffs/uncertainty and smallest next decision or test. Check count, substantive variety, constraint compliance and complete usable descriptions. No count helper is required. A settled option may go to Decision Synthesizer for a consequential choice gate; no execution or external action follows by default.
