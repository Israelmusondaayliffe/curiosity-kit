# Draft

Read the relevant [context](../references/context.md), [channel](../references/channels.md) and supplied sources. Produce the entire requested piece once the necessary material exists. Work section by section only when requested; do not substitute an outline or placeholders for a complete article.

Use maintained guides for their actual scope. With sparse guides, use the user's present language and explicit preferences; clear restrained prose is a fallback, not an invented identity. Match syntax, cadence, register, expressive choices and certainty to evidence. The writer owns their argument, feelings and experience. A consequential alternative thesis is a proposed choice, not a silent rewrite.

Keep material factual claims attached to source support. Personal experience supports what happened to that person; it does not by itself prove a universal pattern. Name assumptions when they matter. Verify unstable or consequential facts through available authoritative sources when required; missing access remains a limitation. Hypothetical examples must be plainly hypothetical. Requested fiction stays within its fictional scope. Reasons, mechanisms and general premises count as claims too: do not state ones the sources lack as fact in the writer's voice, including inside a speculative passage. An open question stays open; a hedged extension is acceptable only when it rests on what the sources say.

Choose structure for the piece. A decision memo may lead with the recommendation; an essay may need a scene; a technical explanation may need terms defined before a conclusion. Use [craft](craft.md) when a hook, thesis, promise, analogy or bridge actually helps. Do not manufacture an ending, urgency, dramatic arc, reader transformation or call to action.

Write concrete nouns and verbs where they clarify. Let sentence length follow thought and the writer's rhythm. Preserve a useful detour, joke, correction, fragment or uncertainty; remove filler and confusing repetition without flattening all texture. Technical vocabulary stays when precise, with explanation for the intended reader. Do not replace source detail with generic claims of importance.

If the user supplied an introduction or exact wording, preserve its requested boundaries and draft only the authorized remainder. Existing project conventions determine filenames and versions. In a newly initialized writing home, a single drafts/<piece-slug>/ folder can hold versions and source notes; do not impose that layout on other projects.

Return usable prose first. Mention an unresolved fact only when it affects use. Child drafting does not start a review team or another full cleanup workflow: return the draft to the parent for [review](../references/review.md) and final delivery. Completion means the requested text exists and fulfills the brief, not that all optional stages have been performed.
