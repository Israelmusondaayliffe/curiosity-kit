# Writing Like Me

Deliver the requested writing or findings. Use the current brief, supplied material and this host's selected guides. Sparse or absent guides never block a usable draft. Do not manufacture the writer's experiences, opinions, feelings, facts or confidence. Preserve purposeful roughness, humor, precise terms and uncertainty.

Read [context](references/context.md) to resolve the actual writing sources and [review](references/review.md) for complete deliverables. This package is independent: all craft, Unslop, claim checks, guide templates and helpers are local. Optional outside help never replaces essential methods.

## Select the requested operation

Carry diagnose, propose, revise or readiness-check through every method. Diagnose returns located findings without changing the supplied artifact. Revise returns complete usable text, not a process report. Ask only for a missing fact or consequential choice that changes the result. A full brief needs no interview; a complete-piece request needs no section approvals.

## Write and finish

Respect the user's requested length, format and number of variants. Use [channels](references/channels.md) for business, articles, LinkedIn or X. The writer owns the thesis; do not replace it with your preferred argument. Factual corrections need evidence. Sources that support one example do not prove a general claim.

For a complete post, article or substantial deliverable, default to two independent reviewers unless the user skips review: Unslop/voice/readability and quality/value/context/intent/support. A tiny correction or incidental reply needs no review team. Each sees the same frozen draft and relevant sources, not the other's findings. Missing reviewers are unavailable; a self-review is never independent. Integrate supported findings once and make at most one focused recheck for an identified repair.

Perform one proportional final Unslop delivery check. Protect exact quotations, code, commands, structured data, citations, links and exact prompt blocks. The scanner supplies candidates, never authorship proof or editorial scores. Deliver the piece first; give only material limitations or requested explanation. Sending and publication require separate authority.

At delivery, propose learning only when there is useful new evidence. Confirm the exact rule and destination before saving. No background learning, cross-host synchronization, source/cache writes or implied approval from choosing a draft. [Helper contract](references/cli.md) defines the local Python interface. A helper's confirmation flag records actual permission; it does not create permission.
