# Research

Read [the host contract](../references/host-contract.md) before access or delegation. This method answers one bounded decision-blocking question in an explicitly selected Matt workflow, for software, knowledge work, or mixed work.

1. State the question, the decision it informs, boundaries (topic, date/version, geography or audience where relevant), and a stop condition. Use supplied constraints; ask only for a missing decision that changes the investigation. Example: “Can this installed library stream partial results without a beta API? Stop when official versioned docs/source and a minimal example establish yes, no, or the exact uncertainty.”
2. Inspect existing approved local notes, specs, datasets, source code and cited evidence first. Determine what is already known and what needs fresh verification. Do not substitute a previous summary for its sources when accuracy depends on details.
3. Delegate to one real background leaf researcher if available and useful while other work continues. Give the exact question, accessible sources, owned output path, scope, evidence format, and stopping condition. The leaf researches directly, with no recursive research delegation. Otherwise do the same bounded investigation in the current session and say so when relevant. A proposed launch is not a running worker.
4. Investigate against high-trust primary sources: official/versioned docs, original specifications, source code, first-party APIs/data, and original research. Trace each material claim to the source that owns it. Public search queries must not disclose private source contents. Record source date/version and access date where volatility matters. Search for disconfirming evidence and resolve conflicting versions explicitly; secondary sources may locate originals but cannot silently replace them.
5. Separate fact, inference, uncertainty, and recommendation. Quote or paraphrase only what the source establishes. Check calculations against inputs and units. If sources cannot settle the question, return the specific gap and a proportional next test; do not widen the task indefinitely or invent facts.
6. Write one durable Markdown answer in the user-approved workstream location, following the existing repository convention. Include: question and decision; concise answer; evidence with citations adjacent to material claims; comparison or worked example if needed; limitations and unresolved conflicts; recommendation and next decision. A non-code example: sample five original policy clauses to decide whether a proposed guidance structure can answer the audience's top questions, distinguishing those observed clauses from conclusions about the whole corpus.
7. Read the saved artifact back, verify citations/paths and audience access, and return the answer, uncertainty, artifact pointer, and next decision now unblocked. Worker completion means actual saved evidence, not an intention to write. No external posting, remote upload, tracker comment, or additional ongoing monitor follows automatically.

Finish when the bounded decision is supported or an explicit source/capability gap prevents it. If the user actually needs a broad research package, explain the wider scope and agree the next work; this library does not require an external sibling skill to complete its bounded research method.
