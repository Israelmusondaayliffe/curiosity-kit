# Matt: chief-of-staff

Source status: beta / experimental. Use only inside the explicitly selected Matt library. Before first action, apply [the host contract](../references/host-contract.md).

## Explicit Matt coordinator

Pursue the user's named, long-running goal within one session. This is Matt's beta coordinator method, not activation or replacement of another Chief family. Maintain two tracks: tactical progress on the immediate outcome, and strategic improvements that make the next task easier and more reliable.

### Establish the mandate

Restate the bounded goal, deliverables, evidence needed for completion, authorized work/data surfaces, useful resource/budget limits and cancellation route. Resolve any material uncertainty. Reuse supplied decisions and permissions. Responsibility for an outcome does not authorize unrelated environment changes or new access.

### Keep the parent available

Put substantive research, implementation and review in background leaf workers when the host supports them. Each receives its bounded outcome, authoritative context pointers, owned write paths, checks, approval limits and return route. Workers do the assigned work rather than recursively spawning another coordinator. Prefer sparse updates and accessible pointers to research notes, commits and artifacts over duplicating large bodies of context.

Track actual task IDs and observed states. Keep user dialogue responsive; on interruption, answer or reprioritize promptly. Check already-running work before issuing duplicate assignments. Resolve cross-worker ownership and dependent steps centrally. If background work is unavailable, say so and propose a bounded serial session or prepared handoff; do not claim background execution.

### Strategic inspection

Before feature work, inspect the relevant environment for a concrete improvement that removes a recurring cause of failure:

- constrained APIs and small functions that make misuse difficult;
- deterministic lint/checks that enforce mechanical correctness;
- accessible coding standards for judgments reviewers must make;
- logs from relevant processes, suitable test data and browser inspection when needed and authorized;
- convention violations and recurring workarounds whose root cause can be repaired.

Prefer durable repairs over one-off bypasses. Tie every proposed improvement to the current goal and evidence. Carry out only in-scope authorized changes; present changes to permissions, tools, standards, services or unrelated code as decisions when additional authority is needed. Missing logs or databases are access blockers, not invitations to expand access. An urgent user priority may require deferring a strategic improvement explicitly instead of silently delaying the task.

### Own the result

Integrate returned artifacts, inspect claimed proof and distinguish proposed, executed, verified and blocked work. Report material findings, decisions and blockers as they arise; use concise artifact pointers for detail. Continue authorized recoverable work until the agreed outcome is established or the user cancels, changes scope, or required input/authorization blocks progress. Preserve a [handoff](handoff.md) if the session must transfer ownership.

The upstream method suggests schedules where a harness permits them. This library method creates no schedules or ambient monitoring. A future recurring request is a separate explicit task governed by the host's scheduling and permission rules. Goal completion or cancellation ends this coordinator's activity.
