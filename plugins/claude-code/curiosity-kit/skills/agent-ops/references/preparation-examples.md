# Optional workflow examples

These preserve useful source examples, not pre-approved execution or schedules. Choose one only when it serves the request. Fill the actual source scope, output, checks, authority and finite boundary using the [local preflight](../playbooks/loop-library.md). Historic numbers below illustrate a bounded example, not universal defaults.

## Three worked shapes

- Research brief: one topic into one named file with a three-sentence summary, capabilities with examples, pricing/access, three nontechnical uses, limitations and sources for major claims. Keep writes in the specified research directory. Finish only when sections and citations are complete. An illustrative boundary is 20 attempts; after three unsuccessful checks of a claim, mark it unverified rather than inventing support.
- Content audit: inspect every selected Markdown draft for title, topic, audience level, practical example and reusable prompt/template. Return an audit plus missing beginner topics, missing examples and topics repeated more than twice. Keep read/write destinations distinct. The original example omitted failure/budget rules; add the task's actual finite boundary and blocked condition before execution.
- Weekly report: selected notes from the previous seven days into a dated report of completed work with dates, open work, decisions and three priorities, at most 500 words in the example. Mention frequency is only a signal, not proof of importance. Resolve timezone, duplicate-run handling, failure behavior and schedule lifetime before any separately authorized scheduling. Preparation stops after producing the definition.

## Eight reusable skeletons

1. Data ingestion: inspect named sources over an explicit recent window, keep decision-changing facts and commitments, deduplicate against prior saved material and produce a dated record. Prove one manual run before considering scheduling.
2. External insight collection: inspect named trusted sources for a defined information need; select useful non-obvious insights, cite them and retain enough provenance to avoid rereading. No particular scraper or external service is required.
3. Internal insight discovery: inspect an authorized time window, identify recurring patterns/gaps and propose concrete next actions checked against current tools and constraints. Distinguish two distinct occurrences from repeated discussion. Keep the action check local.
4. Metric optimization: establish one metric, baseline and target; make one authorized change and remeasure. An example stops at target or five changes. Log each real result; delayed feedback may be appropriate. A metric gain cannot excuse correctness loss.
5. Code delivery: resolve the goal from supplied context, prepare an inspectable plan, obtain required sign-off, implement, review and verify against the original outcome. Role names are not mandatory sibling skills.
6. System improvement: inspect selected recent work for repeated friction. Separate already-authorized low-risk fixes, proposals needing approval and questions needing context. Record actual authorized changes. A source's “auto-approve” label grants no permission.
7. Workflow monitoring: discover selected definitions by an explicit directory/naming rule and inspect their actual run evidence. Report failures and duplicated logic; repair only within current authority. No global registry, automatic refactor or ongoing monitor is created by this example.
8. Goal alignment: compare selected work/results with the user's stated goals, identify evidence-backed drift and one corrective option. A longer-horizon projection is a conditional scenario, not a reliable prediction or inferred new goal.

## Research variants

A deeper research workflow may require citations and several independent supporting facts for major conclusions, a midpoint review and a completion review, with progress read before continuation. One historical example used ten passes and stopped after three repeated queries yielded no new information. Use only checks appropriate to the question; repeated facts are not independent support, and an example cadence does not authorize a timer.

A beginner-facing alternative asks for five recently released open-source tools with name, purpose, dated popularity measure, one use and sources. Skip unverifiable entries after a bounded attempt rather than fabricating the fifth result. The original lacked a total cap; the prepared design must resolve that before execution.
