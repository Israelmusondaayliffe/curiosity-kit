# Explicit bounded advisor execution

## Activate and freeze

Use the actual supported imperative: "Use bounded delegation for this." Record the user's current affirmative request verbatim. Historical Astra/Fable names may identify the method, never a required model. A quoted, conditional, incidental, negated or revoked mention does not activate it. If Gauntlet and this workflow are both selected, or an explicitly observed mutually exclusive Gauntlet run is active, stop before creating state. Optional Codex composition must name one outer owner; never create two authorities.

Inspect the actual workspace, source inputs and native host tools. Check disclosed current workflow ownership before recording peer flags: if ownership is unknown, stop and resolve it. Supply the actual disclosed peer state paths; do not guess a conventional Gauntlet directory or scan private sibling trees. Select only useful workers. Draft the smallest plan: requested result, checkable criteria, task dependencies, exact disjoint output paths, necessary receipt paths, parent integration output, finite launch/concurrency/repair budgets, role choices and stops. Plan and input hashes identify bytes; they do not confer permission. Preserve requested model/effort and record unavailable observations honestly.

Use the [local CLI](../references/cli.md) to validate and initialize only after valid activation. Present the plan/manifest and its contract digest. Obtain the user's applicable approval before any child dispatch and bind its real message/evidence to that digest. Changed inputs, plan or scope require a new approved contract; do not rewrite a frozen run to fit new work.

## Dispatch through the real host

Reserve a launch through the CLI only when its dependencies are accepted and capacity remains. Then invoke the actual supported native child tool with the [worker brief](../references/roles.md), bounded task, relevant input paths/revisions, allowed outputs/receipt and required verification. Do not pass the whole conversation by default or authorize nested spawning implicitly.

Record the actual returned child/session identity and host evidence separately from the reservation. A reservation is not a launched child. Requested identity is not observed identity. A material contradiction of an explicit model/effort request blocks use of that result; if the host cannot expose a field, mark it unknown rather than inventing proof. Missing required runtime capability is blocked, not silently replaced.

Tight polling adds no progress. Observe meaningful host events or a proportionate wait; collect terminal results. Headless parents must remain alive until children finish or confirmed cancellation occurs. A background launch acknowledgement does not prove completion.

## Accept a task result

Inspect returned artifacts and their provenance, command results, all required criteria, changed paths and unresolved issues. Check scope against the approved task, including evidence-file writes. Use the CLI to bind the return to its exact task/attempt, source inputs and current artifact bytes. Failed commands, failed criteria, wrong hashes, missing outputs, widened writes or a failed/blocked return prevent acceptance. A receipt that parses is not proof that its claims are true; inspect actual native records and files.

Compare before/after state outside the permitted outputs at the host verification boundary. Local path checks are not an OS sandbox and cannot detect concealed external activity. Do not accept based on a child saying it complied.

Dependent work begins only after required predecessor results are accepted. Repeated identical receipt submission must not add budget usage or integrate work twice. An identical launch reservation returns the existing record; duplicate completion or review receipts are explicitly refused without another effect. Inspect recorded status after an uncertain response instead of launching again. On interruption, resume the same canonical run, recheck hashes and inspect outstanding real children before launching replacements. A retry consumes the approved remaining repair/launch budget; it cannot reset counters.

## Parent integration and fresh criticism

The parent integrates accepted worker artifacts into the declared integration outputs, using the approved checks. In a two-worker-plus-integration plan, the integration is parent work, not an unnecessary third child. Freeze that actual integrated candidate and its evidence before reserving the critic.

Use a fresh independent native critic with the [critic brief](../references/roles.md), approved criteria and exact candidate/source paths. Do not give it the builder's persuasive narrative. It may not change candidate artifacts; only a specifically approved review receipt may be written. Record actual identity, review coverage, reproduction evidence, required failures and dissent. Check candidate hashes before and after review.

The CLI binds review to the exact successful returns and integrated artifact snapshot. A review over a failed, omitted or different task cannot accept the run. After rejection, the parent uses the explicit `repair` transition before editing: identify the affected tasks or parent integration, bind the rejected review and keep the existing scope and remaining budgets. The transition invalidates affected results and dependent descendants, archives the old integration and retains prior evidence/counters. Reverify the repaired outputs, integrate again and obtain fresh criticism. Existing approval covers this bounded repair; changed plan, inputs or authority require new approval. Do not force revision after passing criteria or average away a required failure.

## Close, stop or transfer

Every observed parent and child side effect counts, including shell commands and redirects: a known write outside the approved roots fails scope and acceptance even when workspace hashes are clean, and is reported, not repaired by deletion. Finalize only when required tasks, parent integration and fresh review meet the approved outcome and every launched child is terminal/accounted for. Write one terminal record and return the actual result and remaining limitations. Parent closure is not a substitute for the user's final acceptance.

Exhaustion, revocation, failed essential checks or unavailable tools stop new dispatch. Cancel only owned outstanding children through supported tools, retain their evidence and report any unconfirmed cancellation. Do not label a still-running child stopped merely to close a record. Use [rescue/context handoff](audit-recovery.md) for bounded continuation or transfer; a new contract does not erase the old run's usage or failures.

The local compatibility record lives at `.fable-advisor/runs/<run_id>/run-manifest.json`, with sibling `run-log.jsonl`. The historical directory name preserves the existing read-only Gauntlet peer probe, not a model or sibling dependency. Its final line records one terminal outcome; status checks must not append activity after closure. Keep these run files outside the distributable skill.
