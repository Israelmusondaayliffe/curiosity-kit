# Design the reader's path

Start from what a reader should be able to produce, decide or check. A topic list is not yet a guide.

## Establish the finish and starting state

Write a practical finish in ordinary language: “save a checked draft invitation” is inspectable; “understand effective communication” is too broad to judge. Identify the reader's prior knowledge, device/access constraints, safe inputs and any prerequisite that can block the first action. Do not label a reader beginner and then assume unexplained specialist vocabulary.

Separate prerequisites from helpful background. Supply a setup alternative when it preserves the promised outcome; narrow the outcome honestly when it does not. Editing a supplied output can demonstrate checking and revision without demonstrating tool operation.

Choose content by function:

- Orientation tells the reader why this task matters and what they will finish.
- Explanation supplies the mental model needed for a decision.
- Procedure supplies exact input, action and recognizable result.
- Practice asks the reader to apply or judge, then provides feedback.
- Reference helps a returning reader find a detail quickly.

These functions may coexist in clearly marked sections. Do not impose four empty document types, split every explanation into a child page or force one paragraph where the concept needs depth.

## Build one complete path first

1. Choose the smallest useful result that demonstrates the main method. Include all inputs needed to attempt it.
2. Order concepts by dependency. Introduce a term through its role in the current example before requiring the reader to use it. Defer theory that does not change the next decision.
3. For each meaningful action, write its starting state, exact action, expected state and interpretation. Where results vary, specify invariants and acceptable variation rather than one magic output.
4. Place a warning or prerequisite before the action it governs. A short condition may come first; a long exception list may need a separate decision step. Avoid hiding the main action inside qualification-heavy prose.
5. Put a completed example before a blank reusable template. Explain decisions at points where a novice would otherwise guess. A filled template without rationale may still be unusable.
6. Add a practice task only when it serves the outcome. Give complete inputs, a decision that requires thought, feedback or a worked answer, and a meaningful next attempt. Copying the demonstrated prompt is setup, not proof of independent ability.
7. Close the path with a save/export/check or explicit stopping decision. Do not finish at an intermediate screen when the reader needs a usable file or approved draft.

Then add a short return path: navigation to troubleshooting, exact syntax or a reusable checklist. The first useful path must not require reading the entire reference section.

## Choose the smallest useful artifact shape

Use one coherent guide when readers share the job and starting state. Use layers within it when beginners need explanation and returning readers need lookup. Use separate artifacts when audiences, permissions or tasks genuinely diverge, such as participant guide and private presenter notes. Parent/child pages earn their place only if a reader can understand the parent and find a necessary child without losing context.

For every proposed section, ask what breaks if it is removed. If nothing breaks and it supplies no useful interpretation, reference or practice, cut it. Conversely, shortening the entry is not a reason to remove a substantive method. Use headings that tell the reader where to act or find a decision, not decorative slogans.

Keep one authoritative explanation of an obligation. Compare meaning within sentences and bullets as well as across sections; references can replace needless restatements. Preserve distinct actors, conditions, exceptions and required output facts. A demonstration, later independent attempt, recap or safety warning at a separate risky action may repeat a principle for a legitimate teaching purpose.

## Check the design before prose polish

Walk from the reader's starting state to the finish. Can each step be attempted with the supplied material? Does each important outcome have a check and an actionable recovery? Does every exercise have feedback? Are private and participant needs separated? Which claims require source or visual evidence? Repair gaps in this path before decorating the artifact or adding more chapters.
