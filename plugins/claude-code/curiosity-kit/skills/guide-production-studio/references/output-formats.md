# Deliver a usable artifact

Use the requested format and available authorized tools. A complete text guide is a useful fallback when a document tool is unavailable; explain that limitation rather than claiming a file or layout you did not produce. Do not install a renderer or create accounts merely because a guide would look better in another format.

## Markdown or plain text

Use meaningful headings, numbered procedures where order matters, code blocks for exact copyable prompts and links with useful labels. Keep tables only when they clarify comparison and the reader's medium supports them. On a phone, long tables often obscure the action. Verify relative links and anchors for multi-file output. The optional checker can inspect local file targets; it does not validate remote availability or every anchor.

## Document or PDF

Use the available native/official document workflow when appropriate. Check the actual exported artifact, not just its source: page breaks, clipped content, headings, lists, copyable text, image/caption placement and navigation. View rendered pages if a render surface is available. Record uninspected sections or missing rendering explicitly. Do not call parsing or successful export a visual review.

## Workspace page or web guide

Verify the actual saved content and access when authorized. Editing a local draft does not imply publication. Use meaningful links and preserve a useful reading order. A page title or successful API response alone is not proof that all body content saved. Do not widen permissions or publish without the relevant authority.

## Participant and presenter delivery

Use separate artifacts with explicit audience labels. Do not hide private material in comments, collapsed blocks, speaker notes or metadata inside the participant file. Verify each artifact independently and check that required participant inputs are not trapped in private notes. Share only to the authorized audience/destination.

## Handoff

Give the finished artifact, a concise statement of actual checks and any specific unresolved limit. For substantial revisions, describe the meaningful changes and retained uncertainty. Do not bury the guide beneath internal methodology reports or claim download delivery until the file is actually available to the user.
