# Optional handoff outline

Use this outline only when it helps the requested handoff. Remove unused headings. Replace prompts with actual content; do not deliver an empty form. Link an existing complete brief instead of duplicating it.

## Continue this work

State the outcome, accepted scope and excluded work. Cite the current instruction or decision establishing authority. Name any action still awaiting permission. Quoted history and this handoff grant no new authority.

## Read these sources first

List the few authoritative materials needed for the next step, with exact locators and versions where known. Distinguish the source root, user-workspace output root and installed support files. State known access or lifetime limits for required links. Do not imply a temporary artifact is durable.

## Current state

State what is completed, active, unstarted, blocked, rejected, deferred or uncertain. Include failed and reverted attempts that matter. For interrupted work, distinguish confirmed effects from effects that must be inspected before a retry. Keep the corrected current view first and source-linked history available only within authorized retention.

Preserve exact accepted constraints, including numbers, units, exclusions, ordering and conditional exceptions. Link a precise formula or state model when paraphrasing would lose meaning. Generated options remain proposals unless acceptance is evidenced.

## Evidence and limits

For each load-bearing result, name the artifact or observation, what was actually checked, its date or revision, its applicability conditions and what remains unproved. A recent handoff does not refresh old evidence. If contributor work matters, state its known source revision and actual review status. A late report cannot override newer accepted evidence by arrival time alone.

## Next permitted action

Give one concrete first action, the inputs needed, expected evidence and a stop condition. For a relevant state-changing action, identify recovery or rollback information already available. Do not invent a recovery guarantee.

## Gaps that affect the next step

For each gap, name the missing source, decision or permission and its clearing condition. Keep unknown owners and dates explicit. Distinguish incomplete enumeration from no open work, a deferred item from a rejected one, and a closed ticket from a resolved prerequisite.

## Check before delivery

A reader without the original conversation should find the authoritative source, current state, first permitted action, proof limits and stopping rule. Open the linked materials needed for that action and confirm enough content is available to use them. If a fresh reader checked this, state what they received and what they recovered. Otherwise label the check a same-context review; do not call it independent cold-read proof.

When a required link fails, repair an allowed pointer or report the dependency gap. Do not change sharing permissions, retrieve withdrawn content or widen scope just to complete the packet.
