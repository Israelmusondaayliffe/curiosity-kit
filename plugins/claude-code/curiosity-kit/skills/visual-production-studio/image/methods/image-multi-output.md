# Request separate image files in one submission

This deliverable is one complete prompt asking for several separate images. Keep it distinct from several prompt submissions, a grid, a contact sheet or a cropped composite.

1. Record the requested number of files and each file's purpose. Identify shared visual DNA: recognition anchors, world, palette roles, material/treatment, graphic language and exact recurring copy.
2. Enumerate every output. Give each its own content, composition, exact text, aspect ratio and useful distinction. Allow explicit exceptions where the page or image has a different job. Shared identity does not require identical layouts.
3. Write one complete submission. State the actual number of separate image outputs, one file per specification, with no grid/collage/contact sheet if that would violate the request. For the preserved eight-image recipe, use eight numbered outputs without turning eight into a general model limit.
4. Retain the chosen format. The system-style `<visual_dna>`, `<images>` and `<verify>` form is reusable operating text; on an ordinary chat it does not acquire a higher system role. JSON or prose can express the same inventory.
5. Before execution, verify whether the selected tool can perform this one-submission operation. If it cannot, the prompt is still deliverable with that limitation. Ask before changing to separate submissions or a different model.
6. If execution is authorized, count actual returned separate files. Report omissions or a returned composite as a shortfall. Do not crop a grid or issue additional silent requests to manufacture success. Each corrective submission needs to remain within the authorized scope.

Deliver the requested batch prompt without splitting its inventory into independent alternative blocks.
