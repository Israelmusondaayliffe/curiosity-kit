# Seedance prompting and optimization

Preserve the selected Seedance version and surface. Read [Seedance profile](../../references/models/seedance.md) for native capabilities and conflicting dated documentation. A 2.0 request does not become 2.5. `sd25-pe` names the dedicated 2.5 optimizer; the source's Seedance-first narrative recipe is separately selectable. Neither is the global video default.

## Choose the requested authoring form

- Ordinary generation/motion: [BUILD](build.md) or [ANIMATE](animate.md), applying this exact model's guidance.
- A 30-second four-beat treatment: select the detailed [narrative templates](../builder/assets/seedance-2.5-templates.md). Preserve its 00–06, 06–14, 14–24, 24–30 rhythm and Subject/Action/Environment/Camera/Style-Light/Sound/Rules/End-state fields when that recipe is requested. They are not provider requirements for every clip.
- Optimize/compile a complex Seedance 2.5 brief or long narrative: use the complete optimizer procedure below and load only its selected task template. The optimizer's clean prompt plus separate UI/API parameters differs from the narrative template; do not combine contradictory format mandates.
- Multiple independent operations: split generation/edit/extension into sequential complete prompts with explicit handoffs. A single native staged request stays one artifact.

## Optimizer procedure

1. Read the brief and [input states](../seedance-optimizer/input-states.md). Preserve identities/counts, relationships, props and ownership, causal event order, scene, spatial relationships and outcome. Missing media does not prevent improving supplied text/reference labels, but does prevent claiming observed detail or verified attachment parameters.
2. Follow the relevant parts of the [complete core workflow](../seedance-optimizer/core-workflow.md): parse the story contract, compile long text into actual visible events rather than narrator exposition, inventory all readable assets in two passes, assign subjects/roles and resolve mapping confidence. User-specified mappings outrank automatic guesses. One single-person reference cannot define two simultaneous characters. Distinguish narrative facts from appearance observations.
3. Assign each used asset a unique borrowed dimension and exclusion. Keep existing labels unchanged when uploads are inaccessible; renumber only from a verified actual upload map when necessary. In a complete inventory, list unused assets individually in the selected optimizer form so enhancement cannot reactivate them. Do not manufacture missing assets. For multiple subjects use the full [organization method](../seedance-optimizer/organizing-multiple-reference-assets.md), with scene activation and spatial relations.
4. Choose exactly one primary task: generation, localized visual/audio edit or extension. Inspect source dimensions/duration when available. Resolve the compatibility gate before native controls: reference generation may deliberately differ from a reference video's specifications, while actual edit/endpoint/extension controls may inherit them. Use the selected surface's documented role/task fields; wording alone cannot guarantee mode selection. Preserve explicit user timing; do not derive fake event timestamps merely from an external total-duration setting.
5. Load only the applicable complete template: [generation](../seedance-optimizer/video-generation-templates.md), [editing and audio editing](../seedance-optimizer/video-editing-template.md), [forward/backward extension](../seedance-optimizer/video-extension-template.md), [keyframes/storyboards/coarse and fine blockout](../seedance-optimizer/keyframe-anchors.md), or [long sequences](../seedance-optimizer/long-videos-and-time-segments.md). Maintain target counts, sole master clip, timeline inheritance, boundary motion/sound and protected content.
6. Translate vague emotion, camera or process wording into observable performance without changing intent. Use the selected [emotion/cinematography/sound/product guidance](../seedance-optimizer/emotion-cinematography-and-sound.md). Bind exact dialogue, language/accent only if specified, speaker/on-screen position and lip-sync timing. Do not turn speech into silence or add unsolicited Mandarin/dialect. Products must move through physically causal states with correct ownership/contact.
7. Deliver the clean prompt in the requested format. The optimizer defaults to one best prompt; requested comparisons remain valid. Keep actual controls, notices and unresolved source-parameter conflicts outside the creative prompt when necessary. See the [complete output example](../seedance-optimizer/output-contract.md). No update/install command is part of this operation.
8. Review the [full task checklist](../seedance-optimizer/final-checklist.md) against the actual brief, selected surface and task. It is a review aid, not a mechanical requirement to include irrelevant labels, negative lists, API parameters or a blanket maximum-detail style.

## Verification boundary

The structural saved-prompt checker accepts plain text and fences, and validates explicit interval continuity. Its mode inference is a convenience hint, not a semantic classifier. Human/agent review must still verify role exclusions, event causality, native task/control compatibility, exact copy and intended operation. Retired-model words in literal scene text and the Sora typeface are not generation routes. A native API guide does not establish entitlement on Flora, a website, or another aggregator.

Source examples and full optimizer knowledge are retained selectively. Live generation requires separate authorized tools and observed outputs; no optimizer self-update, paid API call or asset creation occurs merely from writing a prompt.
