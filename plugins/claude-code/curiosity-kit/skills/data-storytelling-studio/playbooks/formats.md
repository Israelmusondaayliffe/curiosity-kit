# Finish the requested format

This skill keeps ownership of the story through production. Use an available native artifact tool for file mechanics; do not hand off a bare outline and call the request complete. Inputs are the approved brief, checked claims, finished draft, exhibit data and output/access constraints. Inspect the relevant tool's current contract before use.

## Memo or executive readout

Write the complete answer-first artifact: reader question; bounded answer; decisive findings; interpretation; material uncertainty; recommendation or informative conclusion; next action with known owner/condition; nearby sources. A short readout can be Markdown or a native document. Avoid duplicating a full methods appendix when a precise link supplies it. Confirm the file opens and that cited evidence is accessible to the intended reader. The [worked readout](../assets/example-readout.md) is a complete example.

## Full report

Use a short executive summary followed by the argument the reader needs to inspect: scope/definitions, evidence and exhibits, interpretation/alternatives, limitations, conclusions and any requested actions. Put necessary context before dependent claims. Keep detailed derivations or source tables in a labeled methods/appendix section, without moving decision-changing limitations away from the claims.

Produce the actual requested document/PDF through supported tools. Inspect every rendered page for page breaks, orphan headings, clipped charts, readable tables, visible caveats and functioning references. Verify the exported version, not only an editor preview. If only Markdown is available, provide full content and identify the requested native export as unfinished; do not rename Markdown to .docx or .pdf.

## Deck for a live discussion

Build the narrative first, then make actual slides when the tool exists. Each slide asks or answers one question with a supported takeaway title, the necessary evidence, a visible limitation and source. Speaker notes may carry additional detail, but cannot be the only place a decision-changing caveat exists if the deck will circulate without its presenter.

A useful sequence often starts with the decision, frames the metric, presents decisive evidence, addresses an alternative explanation and ends with the proposed choice/condition. Use only as many slides as needed; no mandatory seven-slide ceremony. For each slide prepare its actual title, body/exhibit, source and notes. Maintain shared units, period labels and category names across slides. Render and inspect all slides and any PDF export. Check chart objects against their data as well as pixels. An authored deck narrative is an honest fallback, not a finished PPTX.

## Notebook or analytical appendix

Use when the reader must inspect/reproduce the supplied calculations. Keep the analytical owner's verified work intact. Embed explanation beside the relevant result; identify inputs, environment, parameters, execution order and which cells were actually run. Do not silently rerun untrusted notebooks, install dependencies, call services or change analysis under a storytelling request. A new calculation or execution requires the applicable scope.

When authorized and supported, use an isolated copy and compare results to the checked source. Clear separation of source output and newly executed output matters. A saved notebook with stale cell results is not proof of reproduction. If execution is unavailable, deliver a readable narrative with existing results clearly labeled unrerun and the exact reproducibility gap.

## Dashboard or interactive site

Use only when ongoing monitoring or interaction answers a real need. Specify the audience's recurring questions, metric definitions, source/update cadence, actual last refresh, defaults, filters, comparison windows and empty/error/stale states. Keep missing data distinct from zero. Show denominator/coverage changes when a filter changes them. A static artifact may be sufficient for a one-time decision.

Build through the actual available tool. Inspect real filter interactions, total/selection consistency, legend toggles, narrow viewport, keyboard focus where supported and an honest no-data state. Do not call hardcoded sample figures live data. Do not claim a refresh pipeline exists because a label says "updated." Include an accessible text/table route. Distinguish saved source, local preview, hosted deployment and recipient access.

External publication, new data connections, scheduled refresh, credentials and access changes require their own authority. If hosting is unavailable or unapproved, deliver complete local content/preview if useful and report the exact remaining step. Do not invent an interactive export or upload private analysis to a convenient service.

## Handoff when a separate tool or worker is needed

Pass the work to do, approved brief and evidence locations, permitted reads/writes/actions, exact expected artifact, and remaining checks. Reuse settled decisions. The receiver must use real available tools, preserve source context and return the actual file plus observed limits. Inspect its result before incorporation. A colleague's or model's claim of successful rendering is not your own viewing evidence.
