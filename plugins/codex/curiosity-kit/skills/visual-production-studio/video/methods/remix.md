# Remix an existing visual structure

Require an actual source breakdown or inspectable reference plus a new subject/context. Missing source is not permission to silently substitute the library's example. If necessary, ask which reference to use; [deconstruction](deconstruct.md) can build its evidence first.

1. Extract reusable structure: shot count/duration, major composition changes, effects and their locations, density rhythm, energy arc and memorable moments. Keep confidence/gaps from the source. Distinguish the source's structure from its literal characters, branding or claims.
2. Map each source element to the new brief. Preserve explicit requested inheritance. Decide which effects transfer, which need replacement and which no longer serve the new mood, product or duration. Explain consequential departures, without forcing novelty the user did not request.
3. Plan new continuity: subject identity, costume, props, geography, lighting and causal transitions. Recheck risk when an effect moves to a different kind of subject. [Failure patterns](../builder/references/ai-video-failure-modes.md) and [effects vocabulary](../builder/references/effects-vocabulary.md) are selectively available.
4. Build the new sequence through [BUILD](build.md) and the selected model profile. Explicit family/version stays locked. No model selected means useful neutral prompts; do not inject Seedance syntax or change model merely because the source used it.
5. Maintain a source-to-new shot map: inherited source shot/relationship, adapted element and reason, or a clearly new addition. If duration changes, account for merged, omitted and added beats. A source mapping belongs outside the submitted prompt unless the selected surface needs it.
6. For a detailed treatment, update the effects inventory/counts, rhythm/density and arc; finish with a short changelog of retained/replaced effects and timing/structure changes. For a compact requested prompt, preserve that decision discipline without imposing all report sections.

Check that the result serves the new intent and preserves every requested invariant. Independent submissions get self-contained prompts; one documented native multi-shot submission stays together. Do not claim source fidelity for invented observations or guarantee generated quality before inspecting real outputs.
