# Character hero → bible → board → sequence

Use this four-stage workflow only when persistent-character preproduction is requested or needed. A short animation does not automatically need a character bible. The selected image and video models can differ intentionally; identify each approved stage rather than silently substituting providers.

## A. Establish the hero

Write or refine one canonical character image prompt with the actual identity/design, body proportions, wardrobe/materials and significant details. Preserve the requested aesthetic. A supplied approved image can satisfy this stage without regeneration. Review the actual hero before freezing it as an identity anchor; a prompt alone is not the reference image.

## B. Build readable consistency references

Choose one designed composite or separate turnaround, wardrobe, expression and cinematic-portrait sheets according to requested output and readability. A turnaround may show front, three-quarter, side, back and rear three-quarter views; a head study may depict the requested emotional range. Wardrobe shows construction/material/accessory details that matter for continuity. Reference counts are project choices, not a universal provider budget.

Write each sheet prompt independently complete with the same identity and exact garment/design anchors. For one composite specify distinct regions; for separate files specify true separate outputs, not a disguised collage. Inspect the resulting sheets for identity/wardrobe contradictions and legible useful angles. Once selected, keep them fixed; a motion failure should normally repair motion direction before replacing identity assets. A requested identity revision can legitimately reopen the selected references with explicit versioning.

## C. Create and inspect the storyboard

Use [previs](previs.md). Choose panel count/form from the actual story and duration, distinguishing references from action panels. A combined director's blueprint may contain character views, set plan, lighting, lens notes and storyboard on one sheet; separate resources may be clearer. Neither structure is inherently required. Read the real resulting board before planning Stage D.

## D. Bind references to the video

Record actual uploaded identifiers and their roles. A compact `SUBJECTS` block identifies each visible subject and distinctive appearance. `REFERENCES` assigns each turnaround/wardrobe/expression sheet to consistency only and excludes its layout/labels from the render. `STRUCTURAL GUIDE` binds the board's panel order and action while excluding grid lines, arrows, shot numbers and annotations. `STYLE` defines the requested final medium separately if the board is merely a sketch.

The hero is the identity anchor when that character appears, not an obligation to show them in every frame. Clean opening/closing frames are separate endpoint roles. Map multi-character interactions with clear activation by scene and stable positions; do not blend subjects or transfer wardrobe. Number all assets from actual upload order and check exact family/version/surface cardinality in the selected profile. Legacy caps and preferred-provider claims in source examples are not current native limits.

Write the sequence as actual shots or a documented native staged request. Include coherent action/camera/arrival state, intentional sound and enough visible identity detail to prevent drift. Keep intended cutaways, scene changes, stylization, absence, and deliberate costume changes authorized by the brief. Exact-expression bounds apply only when the user makes them constraints, not automatically because an expression sheet exists.

## Diagnose without destroying continuity

- Sheet/grid appears in output: make its structural/consistency-only role and excluded visual artifacts explicit; verify the correct asset binding.
- Sketch style overrides final style: separate board structure from requested visual medium. Preserve a drawn medium if intentional.
- Face/wardrobe drift: inspect the actual failed shot, check role conflict, strengthen the specific visible anchor and repair the affected segment. Do not blindly repeat contradictory instructions.
- Panel/beat mismatch: restore ordered correspondence or document deliberate compression.
- Reference overload/conflict: prioritize the controlling source per property, remove truly redundant uploads or use a readable composite only if it preserves needed detail. Do not invent a model-wide optimal subject count.

The complete historical [character-bible examples](../builder/references/character-bible-pipeline.md) preserve Bobo, Celestial Voyager, ink-wash and director's-blueprint patterns. They are inspiration/provenance; use this method and current selected profile for active routing, reference roles and support claims. Deliver all requested prompts plus the actual role map and observed-stage status; do not claim unseen stages ran.
