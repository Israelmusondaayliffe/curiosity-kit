Patterns related to Previs-to-Sequence. Use for routing decisions when a request might fit the pattern poorly or fit an adjacent pattern better.

## Single-Frame Reference + Video

**What it is:** One image (character portrait, product shot, environment concept) used as the start frame for image-to-video. No storyboard grid. Text prompt drives motion entirely.

**Relationship to Previs-to-Sequence:** Degraded form of the pattern. Single image instead of a grid. Lower control, faster iteration.

**When to use instead:**
- Sequence is under 5 seconds.
- Only one shot, no camera move variations.
- Subject motion is simple (ambient, idle, slow rotation).
- Speed of iteration matters more than precision.

**Observed pairs:** Ideogram 3.0 + Veo 2, Midjourney + Runway, another image model + Kling.

**Routing:** Use the local [animate method](../../methods/animate.md) for one-image motion.

## Character Sheet + Video

**What it is:** A character reference sheet (turnaround, expressions, costume details) generated by an image model, then used as a reference for video generation alongside a text motion prompt. Solves character consistency without addressing shot-by-shot direction.

**Relationship to Previs-to-Sequence:** Complementary. Often used alongside the canonical pattern as an additional `@Image` reference. The character sheet locks identity. The storyboard locks shot structure.

**When to use alone:**
- Single sustained shot of a named character.
- Identity preservation is the only structural concern.
- No camera grammar variation needed.

**Routing:** Use local [character continuity](../../methods/character-continuity.md) for the requested hero/sheets, then [animate](../../methods/animate.md) for single-shot motion.

**Routing when combining:** Use Previs-to-Sequence proper. Generate the storyboard composite. Add the character sheet as `@Image2` (or higher) in Stage 2. Reference the sheet explicitly in Stage 2 prompt: "Subject identity matches @Image2 character sheet."

## Mood Board + Video

**What it is:** Collection of style reference images (not storyboard panels) fed to the video model as visual anchors for palette, lighting, atmosphere. Motion driven by text prompt.

**Relationship to Previs-to-Sequence:** Adjacent but distinct. Mood boards are aesthetic anchors, not structural ones. Storyboards are structural anchors, not aesthetic ones.

**When to use:**
- Aesthetic fidelity matters more than shot choreography.
- Sequence is simple (one camera move, one subject).
- User has multiple style references but no shot list.

**Observed pairs:** Runway "Image to Video" with multiple reference images. Some Pika and Kling workflows.

**Routing:** Use local [image series](../../../image/methods/image-series.md) for separate mood images or [reference composition](../../../image/methods/image-reference-composer.md) for one composite, then [animate](../../methods/animate.md) with explicit style-reference roles.

## Animatic + Video

**What it is:** A rough animated sequence (often with placeholder audio) generated using traditional tools or simpler AI, then refined or extended by a video model. Three-stage workflow: storyboard, animatic, final video.

**Relationship to Previs-to-Sequence:** Extension of the canonical pattern. Animatic adds an intermediate fidelity check between storyboard and final video.

**When to use:**
- High-stakes commercial work where iteration on timing matters before committing to full video generation.
- Long sequences (over 30 seconds) where chunking through animatics is cheaper than chunked Previs-to-Sequence.

**Routing:** Not yet a skill. Currently a manual workflow with traditional animatic tools (After Effects, Blender) bridging the AI stages.

## JSON Storyboard + Video

**What it is:** Instead of a visual storyboard image, a structured JSON file defines shot list, camera moves, timing, and SFX. Fed programmatically to a video model's API.

**Relationship to Previs-to-Sequence:** Programmatic variant. Replaces the image-model stage with a text-to-JSON stage. Trades visual previsualization for API-level precision.

**When to use:**
- Production pipeline with automated generation at scale.
- API integration (Veo 3 via veotools, n8n workflows).
- The team prefers code-level control over visual reference.

**Observed pairs:** Veo 3 via veotools Python library. Various n8n automations.

**Routing:** the standalone Stage 1 JSON form in this skill (JSON envelope mode) generates structured prompts. Then API workflow handles execution.

## Chunked Narrative (when readability or actual clip limits require it)

**What it is:** Multiple Previs-to-Sequence iterations chained with continuity frames between them. Each chosen segment generated separately, then stitched.

**Relationship to Previs-to-Sequence:** Meta-application of the pattern. Same workflow, repeated, with continuity engineering between segments.

**When to use:**
- Sequence exceeds the chosen editorial segment or verified surface limit.
- Single-call video model limits prevent native generation at full length.
- Narrative has multiple acts or scene changes.

**Workflow:**
1. Build segment 1: Stage 1 storyboard + Stage 2 video.
2. Take the final frame of segment 1's video as the hero frame for segment 2's storyboard.
3. Build segment 2: Stage 1 (using segment 1's end frame as hero) + Stage 2.
4. Repeat for additional segments.
5. Stitch in post (any video editor).

**Routing:** Use Previs-to-Sequence directly, run multiple times. Document the continuity frame strategy in the delivery summary.

## Pattern decision tree

```
User has a creative brief.
├── Single shot, under 5s, simple motion?
│    └── Single-Frame Reference + Video (local animate method)
│
├── Sustained single shot, character identity priority?
│    └── Character Sheet + Video (local character continuity + animate)
│
├── Aesthetic fidelity over shot structure?
│    └── Mood Board + Video (local image series/reference composition + animate)
│
├── Multi-shot, 5 to 25 seconds, choreographed timing?
│    └── Previs-to-Sequence (this skill)
│
├── Beyond the selected clip limit or multi-act?
│    └── Consider Chunked Previs-to-Sequence (this skill, multi-run)
│
├── API-driven production pipeline?
│    └── JSON Storyboard + Video (the standalone Stage 1 JSON form in this skill JSON + API)
│
└── High-stakes commercial, need intermediate timing check?
     └── Animatic workflow (manual, no skill yet)
```

## Adjacent-method routing cues

When the user's request lands at a pattern boundary, route explicitly:

| User says | Route to |
|---|---|
| "Just one shot, animate this image" | [Animate](../../methods/animate.md) |
| "Build me a character sheet first" | [Character continuity](../../methods/character-continuity.md) |
| "I want 5 keyframes, interpolate between them" | Stage2-skeleton 5 (Pika V2.2 Pikaframes) |
| "I want to compare multiple video models from one storyboard" | Previs-to-Sequence + manual model comparison |
| "Build me 10 different storyboard concepts" | requested variation writing within this skill + Previs-to-Sequence |
| "I have a JSON shot list, can you generate panels from it?" | the standalone Stage 1 JSON form in this skill JSON envelope mode |
| "I want a 30-second narrative" | Choose one or multiple segments using the actual surface limit and shot plan |

When in doubt between Previs-to-Sequence and an adjacent pattern, use the current host question control, or ask directly with 2 to 3 mode labels: "Full storyboard pipeline", "Single image + motion", "Character sheet first, then animate".
