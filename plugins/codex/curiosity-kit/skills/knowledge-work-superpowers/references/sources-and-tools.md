# Sources, tools and scope

The skill contains its research, planning, analysis, writing, review and delivery methods locally. Source repositories explain where those methods came from; they are not runtime dependencies, current access guarantees or permission to run donor software. Do not fetch all donors during an ordinary task.

## Real prerequisites

| Work | Required capability | Honest fallback or limit |
|---|---|---|
| Supplied-text research and a text answer | Read the supplied relevant text; preserve its actual scope | Can be completed sequentially without a connector, browser, worker or script. |
| Internal facts | Authorized read access to the owning files or connected service | Use actually supplied records when sufficient; otherwise mark dependent claims unresolved. Public search does not replace private facts. |
| Current public facts | Available primary-source retrieval, and browser access when the source needs it | State exact access/read limits. Never claim a live read from memory, a snippet or a stored URL. |
| Calculations | Suitable deterministic tool, such as native calculator, spreadsheet or Python standard library | Inspect the inputs, units and expected result; report arithmetic as unverified if it could not be checked. |
| Evidence checker (required for a traceable file evidence record) | Python 3.9+ and read access to the explicitly selected record/artifact | If Python is unavailable, continue useful work with equivalent manual checks, state that the checker was unrun, and report the required checker gate as incomplete. Do not install Python automatically. |
| Durable file deliverable | Authorized write location and a supported usable delivery route | Return completed text or a clearly partial artifact if file delivery is unavailable; do not fabricate an attachment/link. |
| PDF/document/deck/sheet or other requested export | Actual format-capable authoring, parsing and viewing tools | Preserve requested content and disclose the missing export/render step. Renaming text is not conversion. |
| Optional independent worker/reviewer | Actual permitted delegation with separate task/context and scoped access | Execute local methods sequentially. Do not label self-review independent or promise a provider that is absent. |
| External sending, publication, account or persistent action | Explicit applicable authority and a supported tool | Prepare the artifact and stop at handoff until authorized. No implicit commercial/live action. |

Use native host tools first, then standard library, then an adequate installed dependency. For a missing indispensable capability, identify the exact affected operation and continue useful independent work. No fixed model name, API credential, particular commercial provider, personal sibling or global routing framework is required by these methods.

Resolve resource paths against the actual installed skill directory, not the task output directory. This matters for the checker: a relative `../bin` from a bundle directory does not locate a skill. Read only the selected playbook and supporting resources needed for the task. Availability of a file does not prove the host loaded or executed it.

## Original capability sources

Earlier Codex and Claude Knowledge Work Superpowers editions and their knowledge-work adaptations inform the local methods. They are attributed capability sources, not required repositories or evidence of current host execution.

All twelve original functions remain local: route, frame, plan, research, analyze, draft, execute, parallel research, review, receive feedback, verify and finish. Six original template functions are selectable parts of one work-record asset. The original structural-check capability is reauthored with an explicit JSON contract; legacy Markdown bundles are not claimed compatible. This avoids a fragile general Markdown parser and forced output filenames without treating schema validity as factual truth.

Earlier knowledge-work adaptations contributed source-inventory, claim-level supersession, complete-output and capability-honesty rules. Some supporting resources were unavailable, so full adaptation parity is not claimed. The local research implementation is complete without their sibling routing or host-specific tool names.

## Evidence boundaries

Source inspection establishes available methods and dependencies. It does not establish installed/cache parity, model quality, a native host pass, comparative superiority, actual public freshness, user comprehension, acceptance or live delivery. A package validator checks structure; the evidence helper checks declared consistency. Both require actual semantic and artifact review for the user's result.

Maintain valid source and license attribution when adapting substantive resources. [Notices](notices.md) preserve the applicable MIT terms and source credits. No original repository, installed donor or account needs to be changed to use this candidate.
