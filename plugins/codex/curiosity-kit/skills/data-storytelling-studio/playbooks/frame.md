# Frame a story from checked evidence

Use for a new artifact, a consequential change in audience/question, or uncertainty about whether the analysis can support the requested message. Inputs are the user's brief and the actual source artifacts, not a summary of filenames.

## Establish the usable brief

Read the checked findings and their method/limitations together. Identify who will consume the artifact, the question it should answer, what the reader already knows, the decision or informative purpose, the time horizon and the delivery constraints. Inspect an existing artifact before replacing it. Reuse settled answers; do not restart an interview because a template has empty fields.

Recover a missing fact from authorized sources when possible. Ask the user only for a consequential choice, such as which audience has priority or which definition governs conflicting results. Offer a recommendation with its tradeoff. Proceed on a reversible, stated presentation assumption when the answer cannot affect evidence or authority. Never assume access, consent, budget or a disputed metric definition.

Write a compact contract, in working notes or [the brief template](../assets/story-brief.md): reader/question; requested artifact; source versions and definitions; intended message; important limits; permitted writes/sharing; how the final result will be inspected. This is a production aid, not the final deliverable.

## Decide whether to proceed

- Checked and applicable: produce the artifact with the analysis's actual caveats.
- Partial but useful: bound the message to supported findings. State what is missing next to the affected claim and explain whether a decision can still be made. A complete account of an inconclusive result is useful work.
- Disputed or materially incomplete: stop the affected conclusion. Return the exact conflict, its source locations, the responsible analytical question and a safe interim artifact. You may write verified portions while keeping the disputed conclusion visibly unresolved.

A status string saying "checked" is insufficient when the supplied material visibly contradicts itself. Compare metric definitions, population, date/window, sampling, currency/unit and inclusion rules. Later publication does not automatically supersede the authoritative analysis. Treat a secondary summary as a derivative, not independent confirmation.

## Choose the smallest complete medium

Use a memo/readout for one bounded decision; a chart plus caption for one quantitative relationship; a report for reasoning/methods that must survive without a presenter; a deck for a live sequence of questions; a dashboard for repeated monitoring; a notebook for inspecting/reproducing calculations; a site for a justified interactive or distribution need. Respect an explicitly requested format. Explain a problematic choice rather than silently substitute it.

A leadership audience does not automatically need slides. A continuously changing number does not automatically justify a service. A dashboard requires definitions, source/update controls and tested interactions. Choose secondary exports only for a distinct consumer or accessibility need. Read [formats](formats.md) before producing the chosen medium.

If the useful form is genuinely uncertain, sketch two structurally different options using the same checked data, for example a segment-first view and an aggregate-first view. Decide against the actual reader question, not cosmetic preference. Do not turn this into a compulsory model competition or claim that a model's preference is audience research.

## Output and check

Return the selected production direction and proceed into drafting when authorized. The brief is ready when another worker can identify the reader's question, authoritative evidence, forbidden inference, requested artifact and stop condition. Missing production tools block that format, not all substantive writing. Use [tools](../references/tools.md) to distinguish an achievable fallback from a falsely completed export.
