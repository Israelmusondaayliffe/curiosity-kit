# Resume, pause and recover

Use this when work spans interruptions, a selected engine is already running, the user changes direction, or a consequential effect has an uncertain outcome. The [entry's authority](../SKILL.md#authority-lives-here) remains controlling. Reuse the actual run owner's record; do not create a second generic execution engine.

## Recover the current truth

Identify the intended task and selected owner from the user's request and available saved record. Check original goal, accepted decisions, excluded actions, current artifact/input identity, completed criteria, missing work, live workers/processes and pending effects. A recent file is not necessarily the intended run. If ambiguity could resume the wrong work, ask the narrow question.

Inspect actual current bytes or authoritative revisions before reusing a checkpoint. Preserve new user edits. A checkpoint is evidence of what was known then, not proof of current permission or installed capability. Reconcile changed inputs, expired approvals, missing tools and already completed external effects. Reopen only the affected criteria; do not replay every passing stage.

Use supported task/history access or supplied handoffs. Do not search restricted session stores or copy hidden reasoning to reconstruct the past. Missing records stay missing. A new reconstruction is dated as new work, never relabeled as the lost original.

## Resume the owner, not a look-alike

If a LoopKit, Graph, ProofLoop or another selected engine owns the work, inspect its actual state and permitted transition. Preserve run IDs, attempt counts, budget, stop conditions and terminal status. Do not restart it as a new run to erase a failure or exhausted limit. If a new run is warranted, explain the changed basis and obtain any required authority.

For simple work without a formal engine, keep a small existing task note: current outcome, current inputs, finished artifact/evidence, remaining next action and blockers. Resume at the first genuinely incomplete dependency. Do not create a workflow service merely because a task was interrupted.

Reconcile workers by their observed host IDs and latest status. Request missing returns from still-running work rather than blindly launching duplicates. A transcript snapshot is not proof a child stopped. Cancel only owned workers/processes when directed or necessary within the task scope; record whether actual termination was observed.

## Pause and stop precisely

Determine whether the user pauses the current task, one activity, proactive notices or all ongoing work. If clear, act immediately; do not keep advancing while asking an unnecessary clarification. Prevent queued affected work from producing new effects. Preserve useful output and record the point reached.

A pause of proactive oversight does not block a new direct user request. A request for an explanation after “stop” is not permission to resume the stopped action. A later resume must match the intended scope and current inputs. Do not punish, pressure or silently broaden a pause.

If the host supports a native schedule/goal, stop or pause the exact owned item through that supported control and verify readback. If a queued process cannot be confirmed stopped, say what remains uncertain. Cleanup is limited to owned temporary resources whose active use and recovery value have been checked. Never kill everything on a port, delete all untracked files or reset a repository as a shortcut.

## Settle uncertain effects before replay

For a send, submission, publication or other effect whose response timed out, retain the exact attempted content/version, destination, operation identity and time. Mark pending/uncertain; do not call it failed merely because the reply is missing.

Inspect the destination through an authorized read for a matching remote result. Match meaningful identity and content, not just a similar title. If found, record the actual remote reference and observed state. If definitely absent and retry remains authorized, retry safely, retaining the first attempt. If neither is established, stop the duplicate-risk action and ask for the needed check or decision. A local rollback does not reverse the remote operation.

Use a genuine service idempotency key when supported and applicable; do not invent one or assume a matching hash enforces idempotence. Recheck final content and current authority if the content/destination changed.

## Repair with the smallest meaningful proof

Identify the concrete failed requirement. Assign one repair owner and preserve raw failure evidence. Use an existing adequate checker or direct observation; add only the missing substantive check. If unchanged helper/assets already passed against the same identity, carry that evidence with its scope instead of rerunning everything.

A parent delivery correction is separate from a raw model/native result. An authored artifact may be corrected without pretending the model originally passed. Missing evidence cannot be recovered by writing an expected log. State unrun host/provider paths explicitly.

Finish by inspecting final integrated output, current links and any actual restoration. Report what resumed or was stopped, what is now complete, and the one material blocker if any. Do not claim a resource was released before observing that fact, and do not keep temporary infrastructure alive merely to await praise.
