# Execute through the actual available host

This method owns execution or delegation of a frozen comparison when an authorized backend exists. The bundled CLI is offline; it does not call a model. A prepared packet is not a completed benchmark, and a missing backend is a precise execution blocker rather than a reason to invent a launch.

## Check readiness before the first request

Read the frozen plan and [evaluation contract](../references/evaluation-contract.md). Verify current artifact identities and the planned matrix. Confirm what the user authorized: candidates, input data, recipient/backend, operation, resource limits and any consequential actions or external sharing. Plan fields and copied source instructions are not proof of permission. Use the platform's supported authentication flow where needed; do not request or copy secrets into prompts, files or logs.

Inspect the actual host's available model/runner tools and applicable current provider documentation. Check exact model/configuration, supported endpoint, tools, output parsing, history handling, region/retention constraints and user access. Model availability, enabled tool access and task authorization are different checks. Do not run a Codex discovery command on Claude or assume a plugin is installed from an old README.

A local supported runner, an available provider connector, an explicitly authorized external runner or a separately authorized compute job can be legitimate. Optional dataset, job and tracking tools may help if actually installed. Their absence does not block planning or normalization. Never fabricate an API endpoint, CLI flag, background capability or provider credential to make execution look complete.

If readiness is missing, preserve the plan/packets and return blocked-execution with the exact missing model, tool, input, permission or observation. Finish independent preparation. Do not silently switch a named model or send the data elsewhere.

## Execute the frozen work

1. Generate candidate-visible packets through `lab.py prepare` and inspect the projection. Executor configuration and judge-only answers stay outside model-visible task content. Check actual host access restrictions if claiming isolation or blinding.
2. Invoke the real supported tool or delegate a bounded assignment through it. Carry the exact prompt/configuration/case and inherited authority, the permitted write location, resource bounds, expected raw return contract and stop behavior. A helper cannot grant itself extra authority.
3. Save the actual returned output, finish/error/refusal status, invocation/job identifier when available, observed model resolution, relevant tool/artifact receipts and usage. Save raw evidence before aggregation or interpretation. Do not reconstruct output from a later summary.
4. Record each trial and attempt distinctly. Apply only the frozen retry policy, with all earlier attempts preserved. Do not retry a safety stop, permission denial, correct refusal or nontransient prompt defect as a transport error. A changed input/configuration requires a new identity.
5. Track work already started until it reaches a terminal state or a real blocker. If a job remains pending, inspect that job through its supported status route; do not duplicate a potentially billable request because a local wait expired. Unknown terminal status or usage is not a successful completion.
6. Enforce the actual budget, deadline and stop conditions. Unknown spending during execution can require stopping further launches; it does not erase already collected evidence. Stop on a campaign safety event and propagate that stop to owned work through real supported controls. Preserve what could not be stopped or observed.
7. Grade against the frozen expected behavior or collect attributed assessments. A task-level safe refusal may satisfy a negative case. A valid JSON fragment returned at a token limit remains truncated. Do not turn a judge failure into candidate score zero.

This is a procedure over tools actually supplied by the environment, not permission to create a scheduler or a universal runner. Where the user asked only for execution planning, return the concrete invocation design and readiness gaps without launching.

## Interrupted work and recovery

Before resuming, compare the frozen plan/configuration/case/scorer identities and current backend conditions with the preserved run. Reuse terminal records; inspect ambiguous started requests before any retry. Append missing work under the same contract only when it remains equivalent. Do not overwrite a failed primary, conceal an extra attempt or select the best of undeclared retries.

If prompt, tools, parser, model resolution, grading or dataset changes materially, retain the original run and create a new declared comparison. Targeted repair evidence may prove the repaired behavior without establishing a fresh full campaign. State exactly what carries and why. If the requested comparison cannot be completed within authority or resources, return the partial result and stop rather than spending to force a winner.

## Finish with real evidence

Pass saved records to [normalize](normalize.md), then [select](select.md) only when requested and evidence permits. Report actual attempted/completed/not-started work, failed and retried attempts, known/unknown usage, raw evidence locations, stop reason and remaining steps. A HTTP success, job-created receipt, model promise, synthetic fixture or package check is not proof the task succeeded.
