# Context and host-local guides

Start with current instructions, the artifact and sources the user selected. Governing host/workspace instructions remain authoritative. Then use the selected writer's VOICE.md, project/publication STYLE.md and relevant curated examples. Fallback craft fills gaps; it is never the writer's identity.

VOICE.md owns sentence sound: syntax, diction, register, cadence, punctuation and evidenced expressive habits. STYLE.md owns claims, support, organization, audience promise and readiness. Split mixed feedback rather than duplicating it. Read ABOUT-ME or SOUL only when explicitly selected or already designated by governing project instructions; do not search unrelated personal files.

## Discovery

Use an explicitly selected writing home first. Otherwise inspect only the active workspace's designated guides. Do not scan the filesystem or the other host. The helper's discover operation reports candidate locations and existence, not guide contents. A missing path remains missing; do not silently create another home. Ask for location only when necessary for a requested save or setup. Draft from supplied evidence meanwhile.

CODEX_HOME and CLAUDE_CONFIG_DIR identify host configuration, not an established writing home. Never infer a writing home from either. Use an actual explicitly designated path. With no declared home, use supplied text and ask for a destination only when setup or saving requires it. Host-local means no cross-host search or synchronization, not a guessed folder convention.

Read relevant guides once per task; refresh after changed instructions or before confirmed writes. Examples teach observable moves, not reusable sentences. Published language is non-reusable unless quotation is requested and attributed. Maintain source certainty and distinctions between observations, interpretations and claims.

Use the project's existing artifact conventions. Only requested setup creates VOICE.md, STYLE.md, examples/ and drafts/. No TASTE.md, status database or extra memory system is required. Legacy TASTE may be read if the active project still designates it; propose splitting rules into voice and style and preserve it until deletion or archival is specifically authorized.
